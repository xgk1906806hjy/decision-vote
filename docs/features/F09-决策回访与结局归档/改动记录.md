## 2026-11-27 · v0.1.1 · 新增

**摘要**：接微信一次性订阅消息，把"到期了记得回来看"变成系统主动推送，解决回访率的最大瓶颈。

**实现内容**
- 新增额度表 `dv_subscribe`：授权一次 `remain + 1`，发送成功 `-1`，上限 `max-remain`（默认 10）
- `GET/POST /api/subscribe/follow-up`：查询/累加提醒额度（前端 `wx.requestSubscribeMessage` 返回 accept 后调用）
- `FollowUpReminderService`：按"到期未填 + 未提醒 + 7 天内到期"筛选候选，逐条校验额度后发送
- `FollowUpReminderJob`：每天 10:00 执行（`app.subscribe.cron` 可改），异常只记日志不中断其他任务
- `WxApiService.sendSubscribeMessage`：调 `cgi-bin/message/subscribe/send`，40001/42001 自动刷新 token 重试一次
- 发送结果分级处理：成功扣额度并写 `reminded_at`；43101/47003 清零额度并标记（不再撞墙）；其他错误留待下轮重试
- `dv_follow_up` 新增 `reminded_at`，作为"这一条推过没有"的幂等标记（与额度分离存储）
- 管理端 `GET /api/admin/reminders`（预览候选）、`POST /api/admin/reminders/run`（手动触发）
- 「我的」页新增回访提醒卡：显示剩余次数、一键开启、模板未配置时给出配置指引
- 降级：模板 ID 未配置 / `WX_MOCK=true` / `FOLLOW_UP_DRY_RUN=true` 三种情况均不报错，只跳过或打印

**验证方式**
- 额度：连续授权 13 次后 `remain` 停在 10（上限生效）；不同用户互不影响
- 候选筛选：把 3 条回访的 `due_at` 分别改为 -2 小时 / -1 天 / -30 天，预览只返回前两条，30 天的被 age 窗口挡掉
- dry-run（`FOLLOW_UP_TMPL_ID=test-template FOLLOW_UP_DRY_RUN=true`）：`candidates=2, sent=0`，日志打印两条待发标题
- 无额度：把某用户 `remain` 置 0 后重跑，`noQuota=1` 且该条**未**被标记，授权后仍可推
- 降级：默认配置（无模板）触发返回 `template-not-configured`；`WX_MOCK=true` 且非 dry-run 返回 `wx-mock`
- 鉴权：管理端接口不带 `X-Admin-Token` 返回 401
- 冒烟脚本 42 项断言全通过（新增 6 项：案例统计 2 项、提醒额度 4 项）

**已知限制（已记入功能说明第 9 节）**
- 提醒只发一次，用户点开未填不会二次催促（一次性订阅的固有限制）
- 授权入口目前只在「我的」页，理想位置是"发布决策成功"后顺势请求，同意率更高

## 2026-11-26 · v0.1.0 · 新增

**摘要**：回访机制上线——发布即埋 3 个月后的时间点，到期后发起者回填结局，形成"决策 → 结果"数据链。

**实现内容**
- `PostService.create` 内自动创建回访计划（`due_at = now + 3 月`，`answered_at` 为空），与建帖同事务
- `POST /api/posts/{id}/follow-up`：仅发起者可填，标签枚举校验，同帖覆盖更新并刷新 `answered_at`
- `GET /api/follow-ups/pending`：到期未填列表（`answered_at IS NULL AND due_at <= now`，升序 20 条）
- 详情接口透出结局：`chosenOptionId` / `outcome` / `outcomeNote` / `outcomeSlot`
- 前端详情页回访区（仅发起者可见）+ 结局展示区；"我的"页待回访清单

**新增文件**
- `backend/src/main/java/com/lukou/decision/controller/FollowUpController.java`
- `backend/src/main/java/com/lukou/decision/service/FollowUpService.java`
- `backend/src/main/java/com/lukou/decision/dto/FollowUpReq.java` / `PendingFollowUpVO.java`
- `backend/src/main/java/com/lukou/decision/entity/FollowUp.java` / `mapper/FollowUpMapper.java`

**涉及/修改文件**
- `backend/src/main/java/com/lukou/decision/service/PostService.java`（`create` 建计划、`detail` 透出结局）
- `backend/src/main/resources/db/schema.sql`（`dv_follow_up`、`uk_post`、`idx_due`）
- `miniprogram/pages/detail/detail.js` / `.wxml` / `.wxss`
- `miniprogram/pages/profile/profile.js` / `.wxml`
- `miniprogram/utils/api.js`（`submitFollowUp` / `pendingFollowUps`）

**验证方式**
- 冒烟脚本断言（4 项）：非发起者提交被拒、发起者提交成功、详情返回结局字段、`/follow-ups/pending` 可调用
- 数据库核对：`dv_follow_up.answered_at` 非空，`chose_option_id` 与所选选项一致

**待补的关键能力（已记入功能说明第 9 节）**
- 无微信订阅消息主动提醒，到期只能被动查看，回访率无保障
- 一帖一条记录，无法支撑 3 个月 / 1 年 / 3 年的多轮回访
