# F04 决策信息流

> **代码位置**：后端 `service/PostService.feed` / `buildCards`、`controller/PostController`；前端 `pages/index/*`
> **状态**：✅ 已实现
> **最后更新**：2026-11-26

## 1. 功能定位

首页广场，按时间倒序展示所有决策卡片。核心是**卡片本身就要表达"这是个什么样的决策"**：场景、参与人数、选项、是否盲投、几条建议——让用户不点进去也能判断值不值得看。

卡片同时是盲投规则的第一道门：未投票的卡片上不显示任何票数分布。

## 2. 用户视角流程

1. 进入首页，加载第 1 页 10 条决策（`loading` 态）
2. 顶部 8 个场景 chip 横向滑动，点击筛选；再点当前 chip 取消筛选
3. 卡片展示：场景标签、标题、处境摘要、选项列表（未投票时只显示"已有 N 人参与"）、建议数
4. 上拉到底自动加载下一页；下拉刷新回到第 1 页
5. 点击卡片进详情；右下角 "+" 进发起页
6. 从发起页/详情页返回时自动刷新（`onShow`）

## 3. 业务规则

| 规则 | 说明 |
|---|---|
| 排序 | `created_at DESC`，纯时间序，无热度加权 |
| 分页 | `page` 最小 1，`size` 默认 10、**上限 50**（后端 `Math.min`） |
| 场景筛选 | `scene` 精确匹配，不传则全部 |
| 摘要截断 | 描述取前 60 字，超出加 `…` |
| 匿名展示 | `anonymous=1` 时 `authorName` 固定为"匿名旅人"、头像置空 |
| 有效状态 | `deadline` 已过即返回 `closed`；`PostStatusJob` 每分钟把过期 `open` 落库为 `closed`，读取侧仍按 `deadline` 兜底 |
| 盲投 | 见下方"盲投判定" |
| 参与人数 | **盲投时仍返回真实 `totalVoteCount`**，只是不返回分布 |

**盲投判定（`PostService.buildCards`）**

```java
boolean revealed = 已登录 && (我是发起者 || 我投过这个帖) || 状态已截止;
vo.setBlind(!revealed);
```

- `revealed = false` 时：每个选项的 `count`、`percent` 强制归零
- 未登录用户（`userId = null`）一律 `blind = true`
- 发起者自己能看到结果

## 4. 数据结构

不新增表，聚合以下表：`dv_post`、`dv_option`、`dv_vote`（`statByPostIds` 聚合）、`dv_comment`（`countByPostIds` 聚合）、`dv_user`。

**卡片返回字段（`PostCardVO`）**

| 字段 | 说明 |
|---|---|
| id / title / summary | 基本信息 |
| scene / anonymous | 场景与匿名标记 |
| authorName / authorAvatar | 匿名时替换为"匿名旅人" |
| createdAt / deadline / status | 时间与状态 |
| options[] | `{id, label, count, percent}`，盲投时 count/percent 为 0 |
| myOptionId | 我投的选项，未投为 null |
| totalVoteCount | 真实参与人数（盲投也返回） |
| blind | `true` = 前端应隐藏分布 |
| commentCount | 建议数 |

## 5. 接口

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/api/posts/feed?page=1&size=10&scene=职场` | 可选 | 信息流 |
| GET | `/api/posts/mine?page=&size=` | 必须 | 我发起的 |
| GET | `/api/posts/voted?page=&size=` | 必须 | 我参与过的 |

**响应结构（`PageResult<PostCardVO>`）**
```json
{
  "code": 0,
  "data": {
    "list": [ { "id": 18, "title": "...", "blind": true, "totalVoteCount": 12, "options": [] } ],
    "total": 37,
    "page": 1,
    "size": 10,
    "hasMore": true
  }
}
```

## 6. 后端实现

| 方法 | 关键逻辑 |
|---|---|
| `feed` | 场景可选过滤 → MyBatis-Plus 分页 → `buildCards` 批量组装 |
| `myPosts` | 按 `user_id` 过滤，同样走 `buildCards` |
| `myVoted` | 先查 `dv_vote` 分页，再按投票时间顺序回捞帖子（用 `LinkedHashMap` 保序） |
| `buildCards` | **批量查询避免 N+1**：一次查选项、一次 `statByPostIds` 聚合票数、一次聚合评论数、一次查我的投票、一次查作者 |

`buildCards` 是信息流性能的核心：列表长度 50 时固定 5 条 SQL，不随卡片数增长。

## 7. 前端实现

| 位置 | 职责 |
|---|---|
| `pages/index/index.js` → `loadFeed(reset)` | 分页拉取，`reset` 决定覆盖还是追加 |
| `onPullDownRefresh` / `onReachBottom` | 下拉刷新 / 上拉加载，受 `hasMore` + `loadingMore` 双重保护 |
| `onSceneTap` | 切换场景时清空列表并回到 `loading` 态 |
| `viewState` | `loading` / `ready` / `empty` / `error` 四态驱动视图 |
| `pages/index/index.wxml` | 盲投卡片：`blind` 为真时不渲染进度条，只显示"N 人参与" |

防重复加载：`onReachBottom` 同时检查 `hasMore` 与 `loadingMore`，避免快速滑动触发多次请求。

## 8. 边界与异常

| 场景 | 表现 |
|---|---|
| 首次加载失败 | `viewState = 'error'`，显示错误信息 + 重试按钮 |
| 加载更多失败 | 保留已有列表（不整页报错），仅结束 loading |
| 列表为空 | `viewState = 'empty'`，引导发起第一个决策 |
| 场景筛选无结果 | 与空态同一视图 |
| 未登录 | 正常返回，全部卡片 `blind = true` |

## 9. 已知限制与待办

- [ ] **排序过于单一**：纯时间序，无热度/质量加权，冷启动期内容少时无感知，量起来后好帖会快速沉底
- [ ] `size` 上限 50，但前端固定 10，暂无个性化配置
- [ ] 无"仅看未投票""仅看已截止"等筛选维度
- [ ] 每次 `onShow` 都整页刷新，从详情返回会丢失滚动位置
- [ ] 卡片不展示作者星星/标签，无法在列表层判断"是谁在提问"
