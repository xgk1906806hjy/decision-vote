# F11 内容安全与举报

> **代码位置**：后端 `service/ContentAuditService`、`entity/Report`、`mapper/ReportMapper`；前端 无
> **状态**：⚠️ 部分实现——内容安全只有本地关键词过滤（未接微信接口），**举报只有表和 Mapper，没有任何接口**
> **最后更新**：2026-11-26

## 1. 功能定位

UGC 产品的合规底线。两件事：

- **发前拦截**：所有用户输入（标题、描述、选项、方案、建议、昵称、简介、经历）过一遍内容安全，命中违禁内容直接拒绝；
- **发后兜底**：用户可以举报违规的决策或评论，平台据此下架。

对个人主体小程序来说，这两项直接决定能不能过审、能不能活下去。

| 敏感词库外置/热更新 | ❌ 未实现 | 硬编码在 Java 常量里，改词要重新部署 |

## 3. 业务规则（当前生效的部分）

| 规则 | 说明 |
|---|---|
| 硬拦截词 | 代开发票、办证、刷单、赌博、博彩、色情、裸聊、加微信领、私聊转账、杀猪盘、传销 → 直接拒绝：「内容包含不适合发布的信息，请修改后再试」 |
| 提示性词 | 傻逼、去死、智障、滚蛋 → 拒绝并提示：「请注意用语，友善的交流更容易被采纳」 |
| 匹配方式 | `toLowerCase().contains()`，前后空格不影响 |
| 空值 | `null` / 空白直接放行，长度校验由各 DTO 的 `@Size` 负责 |
| 检查范围 | 见下表 |

**检查点清单**

| 触发点 | 检查字段 |
|---|---|
| `PostService.create` | 标题、描述、每一个选项 |
| `SolutionService.create` | 方案内容 |
| `CommentService.create` | 建议内容 |
| `UserService.updateProfile` | 昵称、简介 |
| `UserService.addExperience` | 场景、当时怎么选 |

## 4. 数据结构

**表 `dv_report`**（已建，无接口在用）

| 字段 | 说明 |
|---|---|
| target_type | `post` / `comment` |
| target_id | 被举报对象 ID |
| user_id | 举报人 |
| reason | 举报理由 |
| handled | 0 待处理 / 1 已处理 |
| created_at | 时间 |

索引 `idx_target (target_type, target_id)`。

## 5. 接口

**当前没有任何举报接口。** 内容安全是服务内方法，不对外暴露。

规划的接口（未实现，仅为设计建议）：

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| POST | `/api/reports` | 必须 | 举报 `{targetType, targetId, reason}` |
| GET | `/api/admin/reports?handled=0` | 管理员 | 待处理列表 |
| POST | `/api/admin/reports/{id}/handle` | 管理员 | 处置（下架/驳回） |

## 6. 后端实现

`ContentAuditService` 结构上留了扩展位：注释明确写了"生产环境应接入 `security.msgSecCheck`（需要 access_token，服务器出口 IP 需加入白名单）"，但**方法体内只有本地词库判断**，没有 HTTP 调用，也没有读取 `app.content.audit-mock`。

`UserService` 在更新昵称/简介时也调了 `audit.check`，但**没有校验 avatar URL**（外部图片地址可被滥用）。

## 7. 前端实现

无。前端不做任何内容检查，全部依赖后端返回错误文案后 Toast 提示。

## 8. 边界与异常

| 场景 | 表现 |
|---|---|
| 命中硬拦截词 | 400，提示修改后再试 |
| 命中提示性词 | 400，提示注意用语 |
| 词库未覆盖的违规内容 | **直接发布成功**——这是当前最大风险 |
| 变体绕过（拼音、拆字、谐音、图片） | 无任何识别能力 |
| 用户被骚扰/辱骂但未命中词库 | 无举报入口，只能忍着 |

## 9. 已知限制与待办（上线前必须处理）

- [ ] **接入微信 `security.msgSecCheck`**：需要 `access_token`（`getAccessToken` 或稳定版 token）、服务器出口 IP 加白名单、单次 2500 字限制、需要传 `openid`（2.0 版本）与 `scene` 参数。建议做成"先审后发"或"发后秒审 + 命中即隐藏"
- [ ] **`audit-mock` 配置是死的**：`application.yml` 里有这个开关，代码里没读。要么补实现，要么删掉配置避免误导
- [ ] **举报功能必须补**：表结构已就绪，缺 `ReportService` + `ReportController` + 前端举报入口（详情页右上角/建议长按）。这是个人主体 UGC 过审的常见硬性要求
- [ ] 词库硬编码，应外置到配置表或配置中心，支持热更新
- [ ] 无频率限制，恶意用户可以高频发帖刷屏
- [ ] 无图片内容审核（当前产品不支持图片，风险低）
- [ ] 无人工审核后台，`dv_comment.status`、`dv_solution.status` 目前没有任何入口能改成 0
