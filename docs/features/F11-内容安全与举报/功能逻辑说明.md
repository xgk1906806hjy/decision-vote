# F11 内容安全与举报

> **代码位置**：后端 `service/ContentAuditService`、`service/ReportService`、`controller/ReportController`；前端 `pages/detail` 举报入口
> **状态**：✅ 内容安全已实现（本地词库 + 微信 `msgSecCheck`，默认 mock）；**举报提交已可用，缺处置后台**
> **最后更新**：2026-11-27

## 1. 功能定位

UGC 产品的合规底线。两件事：

- **发前拦截**：所有用户输入（标题、描述、选项、方案、建议、昵称、简介、经历）过一遍内容安全，命中违禁内容直接拒绝；
- **发后兜底**：用户可以举报违规的决策或评论，平台据此下架。

对个人主体小程序来说，这两项直接决定能不能过审、能不能活下去。

## 5. 接口

**举报提交已实现**，内容安全仍是服务内方法，不对外暴露。

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| POST | `/api/reports` | 必须 | 举报 `{targetType: post\|comment, targetId, reason}` |

处理顺序（任一步失败即返回 400/404，不写库）：

1. `targetType` 必须在 `post` / `comment` 白名单内，否则「不支持的举报类型」；
2. 目标必须存在：`post` 查 `dv_post`、`comment` 查 `dv_comment`，不存在返回 404；
3. 不能举报自己发布的内容，否则「不能举报自己发布的内容」；
4. 同一用户对同一目标只记一次，重复提交返回「你已经举报过了，我们会尽快处理」。

`reason` 限 255 字，`handled` 初始写 0。

**未实现**（处置后台，仅为设计建议）：

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/api/admin/reports?handled=0` | 管理员 | 待处理列表 |
| POST | `/api/admin/reports/{id}/handle` | 管理员 | 处置（下架/驳回） |

## 6. 后端实现

`ContentAuditService.check(text)` 先过本地词库（硬拦截 + 提示性词），再根据 `app.content.audit-mock` 决定是否调用微信：

1. `audit-mock=true`：只走本地词库，本地开发默认值；
2. `audit-mock=false`：用当前登录用户的 `openid` 调 `wxa/msg_sec_check`，`scene` 默认 3（论坛），`version=2`；
3. `suggest=risky` 直接拒绝，`suggest=review` 提示修改后再试；
4. 微信接口异常时，`fail-open=false`（默认）直接返回 500 拦截，`fail-open=true` 才降级为本地词库并记录错误日志；
5. `access_token` 在 `WxApiService` 内缓存，提前 5 分钟过期；失效错误码 40001/42001 自动刷新重试一次。

`UserService` 在更新昵称/简介时也调了 `audit.check`，但**没有校验 avatar URL**（外部图片地址可被滥用）。举报理由也会过一遍内容安全。

## 7. 前端实现

`pages/detail` 正文卡右下角有「举报该内容」文字入口（`.report-link`，22rpx 浅灰，刻意做得不显眼以免鼓励滥用）。点击流程：

1. `wx.showActionSheet` 弹原因列表：违法违规内容 / 色情低俗 / 广告营销 / 人身攻击 / 虚假信息；
2. 选中后调 `api.report({targetType:'post', targetId, reason})`；
3. 成功 toast「已收到举报，我们会尽快处理」，失败直接把后端 `msg` 弹出来；
4. `reporting` 状态位在请求期间拦住重复点击。

其余输入框不做前端检查，全部依赖后端返回错误文案后 Toast 提示。

## 8. 边界与异常

| 场景 | 表现 |
|---|---|
| 命中硬拦截词 | 400，提示修改后再试 |
| 命中提示性词 | 400，提示注意用语 |
| 词库未覆盖的违规内容 | **直接发布成功**——这是当前最大风险 |
| 变体绕过（拼音、拆字、谐音、图片） | 无任何识别能力 |
| 用户被骚扰/辱骂但未命中词库 | 可走举报入口，但**举报后没有处置后台**，`handled` 始终为 0 |
| 举报后无反馈 | 用户只能看到「已收到」，之后没有任何状态回传 |
