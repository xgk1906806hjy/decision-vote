## 2026-11-27 · v0.1.1 · 新增

**摘要**：案例库增加结局分布聚合统计，用户在读案例前先看到"这类决策到底有多少人后悔"，把案例库从"逐条翻"升级为"先看盘子再看样本"。

**实现内容**
- `GET /api/cases/stats?scene=`：返回全局结局分布（worth/regret/watching/unknown 计数与百分比）+ 场景分布（最多 6 个场景）
- 比例分母取**已表态数**，`unknown` 只计数不参与分母；分母为 0 时比例返回 0
- 口径与列表完全一致（已回访 + 帖子未软删），保证统计数字与列表条数对得上
- 传 `scene` 时顶层统计只看该场景，`scenes` 数组保持全景，筛选时仍能看到全局分布
- 前端案例库顶部新增结局分布卡：比例条 + 色点图例 + 场景分布；无数据时不渲染
- 下拉刷新改为 `Promise.all` 并行拉列表与统计；统计接口失败时静默隐藏卡片，不阻塞列表

**新增文件**
- `backend/src/main/java/com/lukou/decision/dto/CaseStatsVO.java`
- `backend/src/main/java/com/lukou/decision/dto/SceneStatVO.java`

**涉及/修改文件**
- `backend/src/main/java/com/lukou/decision/service/CaseService.java`（新增 `stats` / `percent`）
- `backend/src/main/java/com/lukou/decision/controller/CaseController.java`
- `miniprogram/utils/api.js`（`caseStats`）
- `miniprogram/pages/cases/cases.js` / `.wxml` / `.wxss`
- `docs/02-项目文档.md`（接口表）、`README.md`（Roadmap）

**验证方式**
- 造数验证：把 2 条回访改为 `regret` / `watching` 后，接口返回 `total=8, worth=6, regret=1, watching=1`，比例 `75/13/13`；恢复数据后回到 `8/8/0/0`
- 已软删帖子（`deleted=1`）的回访记录被正确排除（9 条已回访 → 统计 8 条）
- `scene=考研` 返回该场景数字，`scene=跳槽` 返回全 0 但 `scenes` 仍为全景
- `mvnw clean package` 通过，服务重启后接口 200

**已知缺陷（尚未修复，已记入功能说明第 9 节）**
- `stats` 全量遍历已回访记录在内存聚合，量级上来后需改为 `GROUP BY` 由数据库聚合

## 2026-11-26 · v0.1.0 · 新增

**摘要**：回访数据沉淀为可检索案例库，并提供相似案例推荐供发起决策前参考。

**实现内容**
- `GET /api/cases`：已回访决策列表，支持场景筛选、关键词（标题/描述）搜索、分页
- `GET /api/cases/similar`：同场景 + 关键词打分推荐，默认 5 条、上限 20
- 结局中文化统一在 `CaseService.OUTCOME_LABEL`（worth/regret/watching → 值得/后悔/观察中）
- 前端案例库页：场景 chip、搜索框、清空、分页、下拉刷新、区分"完全空"与"筛选空"两种空态
- 发起页选场景后自动拉 3 条相似案例，失败静默不阻塞发布

**新增文件**
- `backend/src/main/java/com/lukou/decision/controller/CaseController.java`
- `backend/src/main/java/com/lukou/decision/service/CaseService.java`
- `backend/src/main/java/com/lukou/decision/dto/CaseVO.java`
- `miniprogram/pages/cases/cases.js` / `.wxml` / `.wxss` / `.json`

**涉及/修改文件**
- `miniprogram/app.json`（注册为 tabBar 页）
- `miniprogram/pages/create/create.js`（`loadSimilarCases`）
- `miniprogram/utils/api.js`（`cases` / `similarCases`）

**验证方式**
- 冒烟脚本断言（3 项）：回访后可查到案例、`outcomeLabel` 正确、`/cases/similar` 可调用并返回列表
- 后端编译通过，前端静态校验通过

**修复记录**
- 冒烟脚本调用中文关键词接口时报错，定位为测试脚本未做 URL 编码，补 `urllib.parse.quote` 后通过（业务代码本身无问题）

**已知缺陷（尚未修复，已记入功能说明第 9 节）**
- `list` 为全量内存过滤 + 内存分页，案例量上千后性能会明显退化，需下推为 SQL 分页
- 相似度按单字符命中计分，语义匹配能力弱
