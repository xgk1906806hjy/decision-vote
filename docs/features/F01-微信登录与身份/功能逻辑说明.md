# F01 微信登录与身份

> **代码位置**：后端 `service/AuthService`、`service/WxApiService`、`controller/FileController`、`util/JwtUtil`、`config/AuthInterceptor`；前端 `utils/api.js`、`app.js`、`pages/login`
> **状态**：✅ 已实现，含主动登录页与头像昵称；当前走本地 mock 登录，生产需关闭 mock 并配置 AppID/Secret
> **最后更新**：2026-11-27

## 1. 功能定位

登录分两层，互不阻塞：

- **静默登录**（`app.onLaunch`）：进小程序就有身份，不注册、不填手机号、不授权头像昵称也能用，用于判断"我投过没""我是不是发起者"
- **主动登录**（`pages/login`）：用户需要头像昵称、或 token 失效后要重新拿身份时走这里，一次 `wx.login` + 可选的微信头像昵称填写

身份只做三件事：区分账号、判断归属、展示署名。不读手机号、通讯录、位置。

## 2. 用户视角流程

1. 打开小程序，`app.onLaunch` 自动调用 `wx.login` 拿 `code`
2. `code` 发到后端 `/api/auth/login`，后端换成 `openid`，找不到用户就自动创建一个（随机昵称如"犹豫的573"）
3. 后端签发 JWT 返回，前端存入本地 `dv_token`
4. 之后每个请求自动带上 `Authorization: Bearer {token}`
5. 用户全程看不到登录页；登录失败也不阻塞浏览

**需要头像昵称时的主动登录**：

1. 「我的」页未登录（401）时展示登录卡，点「微信一键登录」进 `pages/login`
2. 登录页可选：点头像走微信 `chooseAvatar`，点昵称框用 `type="nickname"` 拿微信昵称
3. 勾选协议 → 点「微信一键登录」：`wx.login` 换 token → 若有头像先上传 → 写回资料 → 返回上页
4. 之后也能在「我的 → 编辑资料」里换头像、改昵称，路径完全一样（上传拿路径再 PUT）

## 3. 业务规则

| 规则 | 说明 |
|---|---|
| 身份唯一键 | `dv_user.openid` 唯一索引，一个微信用户对应一条记录 |
| 昵称生成 | 首次登录未传昵称时，从 6 个前缀（路过的/想清楚的/犹豫的/晚睡的/远行的/刚做完决定的）+ 100~999 随机数生成 |
| 昵称更新 | 已存在用户再次登录时，若传了昵称/头像则更新，不传则保留 |
| Token 有效期 | 720 小时（30 天），配置项 `app.jwt.expire-hours` |
| 签名算法 | HS256，密钥来自 `app.jwt.secret`（生产必须替换） |
| 鉴权粒度 | 拦截器**只解析不拦截**；每个接口自行用 `UserContext.require()` 声明是否需要登录 |
| Mock 行为 | `app.wx.mock=true` 时，`openid = "mock_" + abs(code.hashCode())`，同一个 code 稳定映射到同一个 openid，便于本地固定测试账号 |
| 头像上传 | 只收 jpg/png/webp，单张 ≤ 2MB（`UPLOAD_AVATAR_MAX_MB`）；**类型按文件头判断，不看扩展名和 Content-Type** |
| 头像存储 | 落盘 `uploads/avatar/yyyyMM/{uuid}.{ext}`，文件名全部服务端生成；库里存相对路径 `/uploads/...`，渲染时前端拼 `BASE_URL` 的域名 |
| 头像失败处理 | 登录页头像上传失败不阻塞登录（`catch` 成 null），用户仍拿到 token，可稍后在资料编辑里重传 |

## 4. 数据结构

**表 `dv_user`**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT | 主键 |
| openid | VARCHAR(64) | 微信 openid，唯一 |
| nickname | VARCHAR(64) | 昵称 |
| avatar | VARCHAR(512) | 头像 URL |
| bio | VARCHAR(255) | 简介 |
| created_at / updated_at | DATETIME | 创建/更新时间 |
| deleted | TINYINT | 逻辑删除标记 |

## 5. 接口

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| POST | `/api/auth/login` | 否 | code 换 token，可选带昵称/头像 |
| POST | `/api/files/avatar` | 必须 | 上传头像（multipart，字段名 `file`） |
| GET | `/api/health` | 否 | 健康检查，返回 `{"status":"up"}` |
| GET | `/uploads/**` | 否 | 头像静态访问（本地磁盘映射） |

**POST /api/auth/login**

请求：
```json
{ "code": "wx.login 返回的 code", "nickname": "可选", "avatar": "可选" }
```

响应：
```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "token": "eyJhbGciOi...",
    "userId": 12,
    "nickname": "犹豫的573",
    "avatar": null,
    "isNew": true
  }
}
```

**POST /api/files/avatar**

请求：`multipart/form-data`，字段名 `file`，单张 ≤ 2MB。

响应：
```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "path": "/uploads/avatar/202611/aedda99245bc436a99b936801d7ccd22.png",
    "url": "/uploads/avatar/202611/aedda99245bc436a99b936801d7ccd22.png"
  }
}
```

`path` 用于写库（换域名不用刷数据），`url` 是加了 `UPLOAD_PUBLIC_BASE` 前缀的展示地址；没配 `public-base` 时两者相同。

## 6. 后端实现

| 类 | 职责 |
|---|---|
| `WxApiService.code2Openid` | mock 模式直接造 openid；真实模式调 `https://api.weixin.qq.com/sns/jscode2session` |
| `AuthService.login` | 按 openid 查用户 → 不存在则创建 → 存在则更新昵称头像 → 签发 token |
| `JwtUtil` | `create(userId)` 签发，`parse(token)` 解析失败返回 `null`（不抛异常） |
| `AuthInterceptor` | 解析 `Authorization` 头写入 `UserContext`，`afterCompletion` 清理，防止线程复用串号 |
| `UserContext` | `get()` 允许为空、`require()` 为空时抛 401 |
| `FileController.avatar` | 校验登录 → 大小 → 文件头 → 落盘 `uploads/avatar/yyyyMM/` → 返回 path/url |
| `UploadProperties` | `app.upload.*`：目录、对外前缀、头像大小上限 |
| `WebConfig.addResourceHandlers` | 把 `uploads/` 目录映射到 `/uploads/**`，省一个对象存储依赖 |
| `GlobalExceptionHandler` | 单独接 `MaxUploadSizeExceededException`，返回"图片太大了"而不是 500 |

关键点：`AuthInterceptor` 不做拒绝逻辑，这样同一批接口既能游客访问（`get()`），又能要求登录（`require()`），不需要维护两份路径白名单。

## 7. 前端实现

| 位置 | 职责 |
|---|---|
| `utils/api.js` → `login()` | `wx.login` → POST `/auth/login` → 写 storage；可选带昵称 |
| `utils/api.js` → `ensureLogin()` | 有 token 直接 resolve，无 token 才登录 |
| `utils/api.js` → `uploadAvatar()` | `wx.uploadFile` 传 `file`，解析 body 的 `code`；401 时清 token |
| `utils/api.js` → `fileUrl()` | 相对路径拼成完整地址，已是 `http(s)` 的原样返回 |
| `utils/api.js` → `request()` | 自动加 `Authorization`；`code=401` 时清除 token 并 reject |
| `app.js` → `onLaunch` | 静默登录 + 拉一次 profile 缓存到 `globalData`，失败静默忽略 |
| `pages/login` | 微信一键登录 + 协议勾选 + 头像昵称（选填）；登录成功 `navigateBack` |
| `pages/profile` | 401 → `viewState='guest'` 显示登录卡；还没设头像时顶部显示引导条（静默登录的老用户入口）；编辑资料里 `chooseAvatar` 换头像 |

Token 存储键：`dv_token`。

## 8. 边界与异常

| 场景 | 表现 |
|---|---|
| `wx.login` 拿不到 code | 前端 reject `{code:-1, msg:"微信登录失败"}`，页面按未登录处理 |
| 真实模式未配 `WX_APPID` | 后端抛 500「未配置 WX_APPID」 |
| 微信接口返回无 openid | 抛 401，消息带微信 errmsg |
| token 过期/伪造 | `JwtUtil.parse` 返回 null → `UserContext.require()` 抛 401 → 前端清 token，下次请求重新登录 |
| 后端未启动 | 前端 reject「网络异常，请检查后端是否已启动」，首屏仍可展示已缓存内容 |
| 上传非图片 | 文件头不匹配 → 400「只支持 jpg / png / webp 图片」 |
| 上传超 2MB | 容器先拦住 → `MaxUploadSizeExceededException` → 400「图片太大了，请换一张小一点的」 |
| 上传时 token 失效 | 返回 401 → 前端清 token，用户重新登录 |
| 头像传成功但 PUT 失败 | 文件已落盘但库里没更新，用户看到旧头像；重传一次即可（旧文件成孤儿，见待办） |

## 9. 已知限制与待办

- [ ] **mock 模式无安全性**：`WX_MOCK=true` 时任何人构造 code 都能拿到某个身份，仅限本地联调，上线前必须置 `false`
- [ ] 无 token 刷新机制，30 天后用户需重新静默登录（目前无感，风险低）
- [ ] 无退出登录入口，无注销账号能力（如需合规需补）
- [ ] **头像文件只增不删**：换头像/注销不会清理旧文件，长期会攒垃圾；需要时补一个按 `dv_user.avatar` 反向清理的定时任务
- [ ] 头像存本机磁盘，多实例部署会各存各的；要水平扩展得换对象存储（或挂共享盘并配 `UPLOAD_PUBLIC_BASE`）
- [ ] 未接手机号快捷验证，重装微信/换设备仍靠 openid 识别账号
