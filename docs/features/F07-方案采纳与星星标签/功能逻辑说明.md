# F07 方案采纳与星星标签

> **代码位置**：后端 `service/SolutionService.adopt` / `awardCredit` / `revokeCredit`、`service/UserService.profile`；前端 `pages/detail/detail.js` 采纳按钮
> **状态**：✅ 已实现
> **最后更新**：2026-11-26

## 1. 功能定位

这是整个激励体系的地基。**只有发起者能拍板"我采纳了这个方案"**，采纳一次，方案作者得一颗星，并按该决策的场景自动累计标签。

关键在于：**星星和标签是"被采纳"这件事的结果，不是用户自己声明的身份**。所以"职场 ★3"意味着这个人有 3 个职场方案真的被人拿去用了，比任何自封的"人生导师"都可信。

## 2. 用户视角流程

1. 发起者进入自己的决策详情，方案列表每条未采纳方案右侧有"采纳"按钮
2. 点击 → 弹确认框「采纳后方案作者将获得一颗星星及对应领域标签，确认吗？」
3. 确认后该方案出现"已采纳"角标，其他方案的采纳状态被清空
4. 再次点"采纳"（对已采纳方案）→ 取消采纳，作者扣回一颗星
5. 被采纳者下次进入"我的"，看到星星总数 +1、对应场景标签 +1
6. 该方案在其他页面（详情列表）展示时，作者昵称旁会挂星星数与代表场景标签

## 3. 业务规则

| 规则 | 说明 |
|---|---|
| 操作权限 | 仅 `post.user_id == 当前用户`，否则 403「只有发起人可以采纳方案」 |
| 方案归属 | 方案必须存在且 `solution.post_id == postId`，否则 404 |
| 一帖一采纳 | 采纳新方案时，先取消该帖其他已采纳方案并扣回对方星星 |
| 幂等语义 | 对**已采纳**的方案再次调用 = 取消采纳（toggle） |
| 星星计算 | 按 `(user_id, scene)` 累计：无记录则建 1 星，有则 +1 |
| 场景兜底 | `scene` 为空/空白时归入「其他」 |
| 扣回规则 | 取消采纳时 -1，减到 0 则**删除该场景记录**（避免残留 0 星空行） |
| 标签生成 | 系统行为，用户无法自填；展示时取 stars 最高的场景作为代表标签 |
| 总星星 | 各场景 stars 求和，实时计算 |

## 4. 数据结构

**表 `dv_user_credit`**

| 字段 | 说明 |
|---|---|
| user_id + scene | 唯一键 `uk_user_scene` |
| stars | 该场景累计被采纳次数 |

**表 `dv_solution.adopted`**：1 表示该方案被采纳。

## 5. 接口

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| POST | `/api/posts/{id}/adopt?solutionId={sid}` | 必须 | 采纳/取消采纳 |

**响应**
```json
{ "code": 0, "msg": "ok", "data": null }
```

星星不单独提供接口，通过 `GET /api/users/me` 的 `stars` 与 `starTags` 读取（见 F02）。

## 6. 后端实现

`SolutionService.adopt`（`@Transactional`）执行顺序：

1. 查帖 → 不存在 404；`post.user_id != userId` → 403
2. 查方案 → 不存在 / 不属于该帖 / 已隐藏 → 404
3. 取消该帖下其他所有 `adopted = 1` 的方案，逐个 `revokeCredit`
4. 若目标方案**已是采纳态** → 置 0 + `revokeCredit` → 结束（toggle）
5. 否则置 1 + `awardCredit`

`awardCredit` / `revokeCredit` 用 `lambdaQuery.last("limit 1")` 取唯一信用记录，避免 `selectOne` 在多行时抛异常。

整个采纳过程在单事务内完成，星星与采纳状态不会出现一边改一边没改的中间态。

## 7. 前端实现

| 方法 | 职责 |
|---|---|
| `adoptSolution` | `wx.showModal` 二次确认 → 调接口 → 重拉方案列表 → Toast「已采纳」 |
| WXML 权限控制 | `wx:if="{{post.author && !item.adopted}}"` 才显示采纳按钮；已采纳方案不显示按钮，需通过其他入口取消（见第 9 节） |

## 8. 边界与异常

| 场景 | 表现 |
|---|---|
| 非发起者调用 | 403，前端 Toast「只有发起人可以采纳方案」 |
| 方案属于其他帖 | 404「方案不存在」 |
| 采纳后被取消 | 作者星星回落，`stars` 减到 0 时场景记录被删除，标签消失 |
| 帖无场景 | 星星记到「其他」 |
| 并发采纳同一帖两个方案 | 事务串行执行，最后一次生效，星星不会双发 |

## 9. 已知限制与待办

- [ ] **取消采纳无入口**：前端对已采纳方案隐藏了按钮，用户看到"已采纳"后无法取消（接口已支持 toggle）。应改为按钮文案切换为"取消采纳"
- [ ] **无采纳操作日志**：只在 `dv_solution.adopted` 上留了状态，没有独立记录表，出了问题无法追溯是谁在什么时候改的
- [ ] **点赞权重未落地**：设计上"发起者可参考点赞数"，目前只是把 `likeCount` 展示出来，没有任何加权或门槛（如"点赞满 N 才允许采纳"）
- [ ] **星星无上限与风控**：发起者可以给自己的小号刷采纳，缺频率限制与自采纳禁令
- [ ] 采纳后不通知方案作者（无订阅消息）
- [ ] 标签只有"场景 + 次数"，未做"多次采纳自动升级为称号"（如职场 ★5 → 「职场过来人」）
