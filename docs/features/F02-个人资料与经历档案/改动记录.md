## 2026-11-26 · v0.1.1 · 修复

**摘要**：修复经历年限档位映射错误 —— 四个选项被映射成 1/2/3/4 年，「5 年以上」变成了 4 年。

**问题原因**

`pages/profile/profile.js` 用 `expYearIndex + 1` 直接换算，把"选项序号"当成了"年限"。但选项本身是区间（1 年内 / 1–2 年 / 3–5 年 / 5 年以上），并不是等距的 1、2、3、4。

**修复**

引入与选项一一对应的代表值数组：

```js
const YEAR_OPTIONS = ['1 年内', '1–2 年', '3–5 年', '5 年以上'];
const YEAR_VALUES  = [1, 2, 4, 8];
yearsAgo: YEAR_VALUES[this.data.expYearIndex] || YEAR_VALUES[0]
```

"5 年以上"取 8 而不是 5，是为了既区别于 3–5 年档，也不正好压在 5 年边界上。

**涉及文件**
- `miniprogram/pages/profile/profile.js`

**验证方式**
静态检查选项与取值数组长度一致（均为 4），前端语法校验通过。

**遗留**
`yearsAgo` 目前仍以单一整数存储，本质上是区间代表值而非精确年限。若要支撑"某类人 N 年后后悔率"这类统计，后续应改为 `years_min` / `years_max` 两列或直接存区间枚举。
