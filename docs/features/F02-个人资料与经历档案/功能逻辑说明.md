# F02 个人资料与经历档案

> **代码位置**：后端 `service/UserService`、`controller/UserController`；前端 `pages/profile/*`
> **状态**：✅ 已实现（前端已补昵称/简介编辑；头像上传仍缺）
> **最后更新**：2026-11-27

## 1. 功能定位

"我的"页面同时承担三件事：**展示身份资产**（星星与场景标签，即"这个人在哪些领域被采纳过"）、**维护经历档案**（"我做过哪些选择、结果如何"，是后续同频匹配的数据源）、**管理我的决策**（我发起的、我参与过的、待我回访的）。

## 2. 用户视角流程

1. 进入"我的"（tabBar 第三项），顶部显示头像首字、昵称、简介；点「编辑资料」可改昵称和简介
2. 看到星星总数与场景标签（如 `职场 ★3`、`考研 ★1`），这是方案被采纳累计出来的，用户不能自己填
3. 中部"待回访"红点区：到期未回填结局的决策，点击进入详情回访
4. 经历档案区：已添加的经历列表，可删除；点"添加"展开表单（场景 → 当时怎么选 → 距今几年 → 结果如何）
5. 底部 Tab 切换"我发起的 / 我参与过的"两个决策列表，点击进详情
6. 下拉刷新，同时刷新资料、待回访、决策列表

## 3. 业务规则

| 规则 | 说明 |
|---|---|
| 星星来源 | 只能由"方案被采纳"累计，来自 `dv_user_credit`，**用户不可自封** |
| 总星星数 | 各场景 stars 求和，实时计算，不做冗余字段 |
| 场景标签 | 每个场景一条信用记录；列表页展示时取 stars 最高的那个场景作为代表标签 |
| 经历档案字段 | 场景（必填）、当时怎么选（必填）、距今几年、结果标签三选一 |
| 结果标签枚举 | `worth` 值得 / `regret` 后悔 / `watching` 还在观察 |
| 删除权限 | 只能删自己的记录，越权返回 404（不暴露存在性） |
| 昵称限制 | 必填、最长 32 字、过内容安全；简介最长 255 字、过内容安全 |
| 资料编辑 | 前端「编辑资料」展开表单，保存后重新拉取 `GET /api/users/me` 并同步 `app.globalData.profile` |
| 列表分页 | "我发起的"与"我参与过的"前端固定取第 1 页 20 条，未做上拉加载 |

## 4. 数据结构

**表 `dv_experience`（经历档案）**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT | 主键 |
| user_id | BIGINT | 所属用户 |
| scene | VARCHAR(64) | 场景，如 考研/辞职/异地恋/买房 |
| choice | VARCHAR(128) | 当时怎么选的 |
| years_ago | INT | 距今几年 |
| outcome | VARCHAR(16) | worth / regret / watching |
| created_at | DATETIME | 创建时间 |
| deleted | TINYINT | 逻辑删除 |

**表 `dv_user_credit`（场景星星）**

| 字段 | 类型 | 说明 |
|---|---|---|
| user_id + scene | 唯一键 | 一个用户一个场景一条 |
| stars | INT | 该场景累计被采纳次数 |

## 5. 接口

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/api/users/me` | 必须 | 个人资料聚合 |
| PUT | `/api/users/me` | 必须 | 改昵称/头像/简介 |
| POST | `/api/users/me/experiences` | 必须 | 新增经历 |
| DELETE | `/api/users/me/experiences/{id}` | 必须 | 删除经历 |

**GET /api/users/me 响应**
```json
{
  "code": 0,
  "data": {
    "id": 3,
    "nickname": "想清楚的428",
    "avatar": null,
    "bio": null,
    "postCount": 2,
    "voteCount": 5,
    "experienceCount": 1,
    "stars": 4,
    "starTags": [
      { "scene": "职场", "stars": 3 },
      { "scene": "考研", "stars": 1 }
    ],
    "experiences": [
      { "id": 7, "scene": "考研", "choice": "二战上岸", "yearsAgo": 2, "outcome": "worth" }
    ]
  }
}
```

**POST /api/users/me/experiences 请求**
```json
{ "scene": "考研", "choice": "二战上岸", "yearsAgo": 2, "outcome": "worth" }
```

## 6. 后端实现

| 方法 | 关键逻辑 |
|---|---|
| `UserService.profile` | 并行统计 postCount / voteCount / experiences / credits；credits 按 stars 倒序，求和得 stars |
| `UserService.updateProfile` | 昵称非空才更新、长度 >32 拒绝、过审；头像直接覆盖；bio 过审 |
| `UserService.addExperience` | 校验 outcome 枚举 → 场景与选择过审 → 落库 |
| `UserService.deleteExperience` | 查记录 → 校验 `user_id` 归属 → 逻辑删除 |

## 7. 前端实现

| 文件 | 职责 |
|---|---|
| `pages/profile/profile.js` | 资料/待回访/决策列表三路加载；Tab 切换；资料编辑；经历表单增删 |
| `pages/profile/profile.wxml` | 资料卡 + 编辑表单 + 星星标签 + 待回访 + 经历档案 + 决策列表 |

| `profile.js → saveExperience` | 用 `YEAR_VALUES = [1,2,4,8]` 与档位一一映射，不再用 `index + 1` |
| `profile.js → deleteExperience` | `wx.showModal` 二次确认后调删除接口 |

## 8. 边界与异常

| 场景 | 表现 |
|---|---|
| 未登录访问 | 后端 401，前端 `viewState = 'error'` 显示错误态 |
| 无昵称 | 前端兜底显示"路口用户"，头像用昵称首字 |
| 删除他人经历 | 后端 404「记录不存在」 |
| 经历为空 | 显示空态引导，不报错 |
| 待回访接口失败 | 静默置空列表，不影响主体内容（该接口非关键路径） |
