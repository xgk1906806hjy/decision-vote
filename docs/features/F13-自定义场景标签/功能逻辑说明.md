# F13 自定义场景标签

> **代码位置**：后端 `service/SceneService`、`controller/SceneController`、`service/PostService.create`；前端 `pages/create`（录入）、`pages/index` / `pages/cases`（筛选 chip）
> **状态**：✅ 已实现
> **最后更新**：2026-11-27

## 1. 功能定位

8 个预设场景覆盖不了真实处境——"考公""回老家""体制内""要不要生二胎"这类决策，硬塞进"其他"会让同类人永远碰不到彼此。所以场景改成 **预设 + 用户自定义**：用户可以自己写标签，写过的标签会沉淀成站内热词，出现在首页和案例库的筛选条里。

场景是"把同类人聚到同一个池子"的唯一手段，也是相似案例推荐、星星标签、结局统计的分组键，所以它必须允许生长。

## 2. 用户视角流程

**发布时**

1. 进入发布页，场景 chip 行显示 `预设 8 个 + 站内自定义（按热度最多 6 个）`
2. 想选的没有？点 `+ 自定义`，chip 行下方出现输入框，提示"比如：考公、回老家、体制内（2–10 字）"
3. 输入时 `scene` 实时同步为输入值，同时触发一次相似案例查询（仅按当前值查一次，不随每字刷新）
4. 校验通过后发布，帖子带上这个新标签

**浏览时**

1. 首页/案例库的场景 chip 由 `GET /api/scenes` 下发，自定义标签按帖子数倒序排到预设后面
2. 点自定义 chip 等同预设 chip：首页按 `scene` 过滤 feed，案例库同时刷新统计
3. 案例库的"场景分布"统计天然包含自定义场景（统计按库里真实 `scene` 分组）

## 3. 业务规则

| 规则 | 说明 |
|---|---|
| 预设场景 | 职场、感情、考研、留学、买房、创业、家庭、其他，固定在最前，顺序即展示顺序 |
| 自定义长度 | 2–10 字（前端拦 <2，前后端都拦 >10） |
| 唯一性策略 | **不做去重合并**：用户写"考公"和"公务员"会被当成两个场景。宁可分裂也不擅自合并，避免把不同处境强行归一 |
| 自定义数量 | 列表里最多追加 6 个（按帖子数倒序），避免 chip 行无限长 |
| 场景必填 | 空场景直接拒绝（400「请选择所属场景」），因为它是分组键 |
| 内容安全 | 自定义标签走 `ContentAuditService.check()`，与标题正文同一套词库 + 微信 `msgSecCheck` |
| 存储 | 仍是 `dv_post.scene VARCHAR(32)`，**不建场景表**：场景是标签不是实体，独立表会带来同步与删除歧义 |
| 排序依据 | `GROUP BY scene ORDER BY COUNT(*) DESC LIMIT 40`，再由 Java 去重追加，跳过预设项 |

## 4. 数据结构

无新表。复用 `dv_post.scene`：

| 字段 | 类型 | 说明 |
|---|---|---|
| scene | VARCHAR(32) | 场景标签，预设值或用户自定义（≤10 字） |

建议索引（数据量上来后加）：`KEY idx_scene_deleted (scene, deleted)`，支撑 `GROUP BY scene` 与 feed 的场景过滤。

**`GET /api/scenes` 返回**

```json
["职场", "感情", "考研", "留学", "买房", "创业", "家庭", "其他", "考公"]
```

## 5. 接口

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/api/scenes` | 否 | 预设 + 站内热门自定义场景 |
| POST | `/api/posts` | 必须 | 复用，`scene` 允许自定义值 |

场景校验在 `PostService.create` 内，不新增接口，发布路径保持一条。

## 6. 后端实现

| 位置 | 关键逻辑 |
|---|---|
| `SceneService.PRESET` | 8 个预设，前后端顺序一致 |
| `SceneService.list()` | 一条聚合 SQL 取 `scene + COUNT(*)`，`LIMIT 40` 后在内存里跳过预设、追加最多 6 个 |
| `SceneService.normalize(String)` | trim → 空则 400 → 超 10 字则 400，返回归一化值 |
| `PostService.create` | `normalize` → `audit.check(scene)` → 落库，与标题正文同等对待 |
| `PostService.feed` | `scene` 非空时 `eq(Post::getScene, scene)`，自定义与预设无差别 |

`selectMaps` 走 MyBatis-Plus 的逻辑删除，软删帖不会进入热词统计。

## 7. 前端实现

| 位置 | 职责 |
|---|---|
| `pages/create/create.js → loadScenes` | 进页面拉一次场景列表，失败保持本地 8 个预设兜底 |
| `onSceneTap` | 点预设 chip：切换选中并关掉自定义输入框 |
| `toggleCustomScene` | 开/关自定义输入框，开启时 `scene` 取已输入值 |
| `onCustomSceneInput` | 输入即同步 `scene`（trim 后），保证提交值就是看到的字 |
| `pages/create/create.wxml` | chip 行末尾加虚线 `+ 自定义` chip，选中态与预设一致 |
| `pages/index/index.js → loadScenes` | 首页 chip 数据源改为接口，失败回退预设 |
| `pages/cases/cases.js → loadScenes` | 同上；切场景时统计与列表一起刷新 |

样式上 `chip-custom` 用虚线边框区分"预设"与"可输入"，不做第二套配色，避免视觉噪音。

## 8. 边界与异常

| 场景 | 表现 |
|---|---|
| 场景为空 | 400「请选择所属场景」 |
| 超过 10 字 | 400「场景标签最多 10 字」，前端也会先拦一次 |
| 全空格 | trim 后为空，按空处理 |
| 含敏感词 | 内容安全拒绝，文案与标题正文一致 |
| 自定义场景只有 1 帖 | 仍会出现在 chip 里（热度低排在后面），不隐藏 |
| 场景列表接口失败 | 前端保留本地 8 个预设，发布不受影响 |
| 同一场景大小写/空格差异 | 后端存 trim 后的原值，不做大小写归一（中文场景无此问题） |

## 9. 已知限制与待办

- [ ] **不做同义合并**："考公/公务员/体制内"会各自成池，池子被切碎后相似推荐命中率下降。后续可加一张 `scene_alias(alias → canonical)` 映射表做展示层归一
- [ ] **没有管理后台**：错别字、恶意场景（如用标签做广告）只能靠举报隐藏帖子，标签本身清不掉。需要补"场景管理"：重命名/合并/隐藏
- [ ] **热词无时间衰减**：`COUNT(*)` 是历史总量，老热词会长期占据 chip 位；应改为近 90 天计数
- [ ] 场景列表无缓存，每次进首页/发布页各查一次聚合；量级上来后加 5 分钟本地缓存
- [ ] 经历档案（`dv_experience.scene`）仍只允许预设场景，未同步放开
