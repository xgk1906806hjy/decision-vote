# F05 投票与盲投

> **代码位置**：后端 `service/VoteService`、`service/PostService.buildCards`、`controller/VoteController`；前端 `pages/detail/detail.js` 投票区
> **状态**：✅ 已实现
> **最后更新**：2026-11-26

## 1. 功能定位

产品的核心差异机制之一。**投票时看不到任何票数分布，投完才揭晓**——目的是掐掉从众效应：一旦进度条挂在眼前，后面的人投的就不是自己的判断，而是"看起来会赢的那个"。

这与"让走过这条路的人说真话"的内核一致：每一票都必须是独立判断，否则统计出来的多数毫无参考价值。

## 2. 用户视角流程

1. 进详情页，投票区显示选项列表 + 提示"盲投模式：投完后才能看到大家的选择"
2. 选项旁**不显示百分比、不显示进度条**，只显示"N 人参与"
3. 点选一个选项 → 高亮 → 点"确认投票"
4. 提交成功：整块区域就地变成结果视图（进度条 + 百分比 + 我的选择标记），伴随轻震动与"已投票，结果揭晓"提示
5. 已投票用户再次进入，直接看到结果；`myOptionId` 标记我投了哪项
6. 截止后所有人（含未投票者）都能看到结果

## 3. 业务规则

| 规则 | 说明 |
|---|---|
| 一人一票 | `dv_vote` 上 `UNIQUE KEY uk_post_user (post_id, user_id)` 兜底，重复投票被数据库拦下 |
| 投票时机 | `status = closed` 或 `deadline` 已过 → 拒绝，提示「这个话题已经结束投票了」 |
| 选项合法性 | 选项必须存在且 `option.post_id == postId`，否则「选项不存在」 |
| 揭晓条件 | 已登录 且（我是发起者 或 我投过）或 已截止 → `blind = false` |
| 参与人数 | 盲投时**仍返回真实人数**，避免"这帖没人看"的错觉影响参与意愿 |
| 不可撤票 | 无撤销接口，投出即定 |
| 返回体 | 投票成功后直接返回**完整详情**（含揭晓后的分布），前端无需二次请求即可就地展开 |

## 4. 数据结构

**表 `dv_vote`**

| 字段 | 说明 |
|---|---|
| post_id / option_id / user_id | 三元组 |
| created_at | 投票时间（"我参与过的"按它倒序） |
| UNIQUE (post_id, user_id) | 防重复投票的最终防线 |

票数不冗余在 `dv_option` 上，而是每次 `GROUP BY option_id` 实时统计（`VoteMapper.statByPostIds`），避免计票不一致。

## 5. 接口

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| POST | `/api/posts/{id}/vote` | 必须 | 投票，返回揭晓后的详情 |

**请求**
```json
{ "optionId": 42 }
```

**响应**：`PostDetailVO`，其中 `blind` 变为 `false`，`options[].count/percent` 为真实值，`myOptionId` 为我投的选项。

## 6. 后端实现

`VoteService.vote`（`@Transactional`）：

1. 查帖 → 不存在 404
2. `status == "closed"` 或 `now > deadline` → 400
3. 查选项 → 不属于该帖 → 400
4. `insert` 投票，捕获 `DuplicateKeyException` → 400「你已经投过票了」

`VoteController.vote` 在 service 成功后调用 `postService.detail(id, userId)` 返回——此时 `myVoteMap` 已包含该帖，`revealed = true`，所以同一个响应就把结果带回去了。

盲投判定放在 `PostService.buildCards`，**列表与详情共用同一份逻辑**，避免两处规则漂移（这是之前修过一次的坑，详见改动记录）。

## 7. 前端实现

| 方法 | 职责 |
|---|---|
| `onSelectOption` | 已投票或已截止直接 return；否则记录 `selectedOptionId` |
| `submitVote` | 调接口 → `decorate(post)` → `voted = true` → `revealAnim = true` → `wx.vibrateShort` → 重新拉方案列表 |
| WXML | `wx:if="{{!post.blind}}"` 才渲染百分比与进度条；`blind` 为真时显示"N 人参与" |

揭晓是**就地展开**而非跳页/刷新，视觉上更接近"刮开"的体验；`revealAnim` 用于给进度条一个生长过渡。

## 8. 边界与异常

| 场景 | 表现 |
|---|---|
| 重复投票（并发双击） | 唯一约束拦下，第二次返回 400「你已经投过票了」 |
| 截止后再投 | 400，前端 Toast 提示 |
| 未登录投票 | 401，前端提示后需重新进入（无自动重试） |
| 选项参数缺失 | `@Valid` 触发 400 |
| 投票成功但方案列表刷新失败 | 投票结果已揭示，方案区保持旧数据，不阻塞 |

## 9. 已知限制与待办

- [ ] **无投票资格校验**：产品设计里"只有过来人能答"目前只体现在建议与方案上，投票仍是任意用户可投。若要收紧，需要按经历档案做资格判定
- [ ] 不可撤销/改票
- [ ] 显示参与人数仍可能产生轻微从众（"人多的帖更值得投"），但优于显示分布，暂保留
- [ ] 无防刷机制（新账号批量投票），上线前需加设备/频率限制
- [ ] 票数实时 `GROUP BY`，帖子量级上来后需加缓存或冗余计数字段
