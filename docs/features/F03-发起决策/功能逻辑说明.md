# F03 发起决策

> **代码位置**：后端 `service/PostService.create`、`controller/PostController.create`；前端 `pages/create/*`
> **状态**：✅ 已实现
> **最后更新**：2026-11-26

## 1. 功能定位

把一个纠结的人生选择结构化地抛出来：**标题 + 处境描述 + 所属场景 + 2~6 个选项**。场景是后续一切推荐与匹配的基础（案例库筛选、相似案例推荐、采纳后的标签归属），所以它是必填项而不是装饰。

发起时前端会**主动推送同场景的历史案例**，让用户在提问前先看看别人怎么选的——这是"先给参考，再谈提问"的产品意图。

## 2. 用户视角流程

1. 首页右下角 "+" 进入发起页
2. 填标题（一句话说清在纠结什么）
3. 写处境：现在什么情况、纠结点在哪、有什么约束
4. 选场景（8 个 chip，选中后**自动加载 3 条同场景历史案例**展示在下方，可点进去看结局）
5. 填选项，默认 2 个，可增到 6 个、可删到只剩 2 个
6. 选择是否匿名（匿名后信息流显示"匿名旅人"，但发起者身份在后端仍可判定）
7. 选投票期限：不设截止 / 1 天 / 3 天（默认）/ 7 天
8. 提交 → 成功 Toast → `redirectTo` 详情页

## 3. 业务规则

| 规则 | 说明 |
|---|---|
| 标题 | 必填，≤60 字 |
| 处境描述 | 必填，≤2000 字 |
| 选项数量 | 2~6 个；后端会 trim、去空、去重后再校验，去重后不足 2 个直接拒绝 |
| 单个选项 | ≤40 字 |
| 场景 | 前端必选，**后端未做强校验**（见第 9 节） |
| 投票期限 | `deadlineHours` 为空表示不设截止；仅当值 > 0 时才写入 `deadline = now + N 小时` |
| 初始状态 | `status = open`，`view_count = 0` |
| 内容安全 | 标题、描述、每个选项都要过审 |
| 副作用 | **发布时自动创建一条回访计划**，`due_at = 当前时间 + 3 个月`（F09 的数据起点） |
| 匿名 | 只影响展示名，`post.user_id` 仍存真实用户，发起者权限判断不受影响 |

## 4. 数据结构

**表 `dv_post`**

| 字段 | 说明 |
|---|---|
| user_id | 发起者 |
| title / content | 标题与描述 |
| scene | 场景 |
| anonymous | 1 = 匿名展示 |
| deadline | 投票截止时间，可空 |
| status | open / closed（`closed` 由截止时间推算，不落库改写） |
| view_count | 浏览量，每次进详情 +1 |

**表 `dv_option`**：`post_id` + `label` + `sort_no`（按 0,1,2… 写入，保证展示顺序稳定）

## 5. 接口

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| POST | `/api/posts` | 必须 | 创建决策 |

**请求**
```json
{
  "title": "35 岁被裁，要不要接降薪 30% 的 offer",
  "content": "房贷还有 12 年，孩子明年上小学…",
  "scene": "职场",
  "anonymous": 0,
  "deadlineHours": 72,
  "options": ["接，先保住现金流", "不接，继续找", "接但继续骑驴找马"]
}
```

**响应**
```json
{ "code": 0, "msg": "ok", "data": { "id": 18 } }
```

## 6. 后端实现

`PostService.create`（`@Transactional`）执行顺序：

1. 清洗选项（`trim` → 去空 → `distinct`）→ 校验 2~6 个、单个 ≤40 字
2. 内容安全：标题 → 描述 → 逐个选项
3. 落 `dv_post`（`status = open`，`deadline` 按 `deadlineHours` 计算）
4. 按顺序落 `dv_option`，`sort_no` 从 0 递增
5. 落 `dv_follow_up`：`due_at = now + 3 个月`，`answered_at` 为空

失败时整笔回滚，不会出现"帖建了但选项没建"。

## 7. 前端实现

| 文件 | 职责 |
|---|---|
| `pages/create/create.js` | 表单状态、选项增删、场景选择触发相似案例、提交校验 |
| `pages/create/create.wxml` | 表单结构 + 相似案例卡片 |
| `pages/create/create.json` | 导航标题「发起一个决策」 |

关键常量：`SCENES`（8 个）、`DEADLINES`（不设截止 / 1 天 / 3 天 / 7 天，默认 index=2）。选项用 `key` 自增而非索引做 `wx:key`，避免删除中间项时输入框内容错位。

前端提交前做同样校验（标题/处境/场景/≥2 选项），避免无意义请求；错误信息用 Toast 提示。

## 8. 边界与异常

| 场景 | 表现 |
|---|---|
| 选项重复（填了两个一样的） | 后端去重后不足 2 个 → 400「至少要有两个不同的选项」 |
| 选项超过 6 个 | 前端阻止添加并提示；后端 `@Size(max=6)` + 业务校验双重拦截 |
| 未登录 | 401，前端提示后停留当前页（输入内容不丢失） |
| 内容命中违禁词 | 400，返回具体提示「内容包含不适合发布的信息，请修改后再试」 |
| 提交成功但跳转失败 | 已落库，用户可从首页信息流看到 |

## 9. 已知限制与待办

- [ ] **场景后端未强校验**：`scene` 为空也能创建成功，会导致该帖无法被案例库筛选、采纳时不产生有效标签（会落到"其他"）。建议后端加白名单校验
- [ ] 不支持配图/附件
- [ ] 不支持草稿保存，退出即丢失
- [ ] 选项不支持"补充说明"，只有 label
- [ ] 回访时间固定 3 个月，用户不可选 6 个月 / 1 年
