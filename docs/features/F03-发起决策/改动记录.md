## 2026-11-27 · v0.1.2 · 优化

**摘要**：过期决策的 `status` 由定时任务落库，避免只有读取侧临时判断。

**实现内容**
- 新增 `PostStatusJob`，默认每 60 秒扫描一次，把 `deadline <= now()` 且仍为 `open` 的 `dv_post` 更新为 `closed`
- `PostService.effectiveStatus` 与 `VoteService` 的 `deadline` 校验保留，定时任务延迟时仍能保证“截止后不可投、结果可见”
- 间隔可用 `POST_CLOSE_INTERVAL_MS` 覆盖，首次延迟可用 `POST_CLOSE_INITIAL_DELAY_MS` 覆盖

**涉及文件**
- `backend/src/main/java/com/lukou/decision/DecisionApplication.java`（`@EnableScheduling`）
- `backend/src/main/java/com/lukou/decision/job/PostStatusJob.java`（新增）
- `backend/src/main/resources/application.yml`

**验证方式**
- 后端 `mvnw clean package` 通过
- 启动日志可见定时任务执行 `UPDATE dv_post ... status='closed'`
- `smoke_test.py` 35 项断言全部通过

## 2026-11-26 · v0.1.0 · 新增

**摘要**：完成发起决策全链路，发布即自动创建回访计划，场景选择联动历史案例推荐。

**实现内容**
- `POST /api/posts`：标题/描述/场景/匿名/期限/选项，事务内完成帖 + 选项 + 回访计划三笔写入
- 选项清洗规则：trim → 去空 → distinct → 校验 2~6 个、单个 ≤40 字
- 内容安全覆盖标题、描述、每个选项
- 前端 `pages/create`：表单、选项动态增删（用自增 key 防输入错位）、匿名开关、期限选择
- 选场景时自动调 `/api/cases/similar?limit=3` 展示同场景历史案例，点击可跳详情
- 提交成功 `redirectTo` 详情页，避免返回时重复提交

**涉及文件**
- `backend/src/main/java/com/lukou/decision/controller/PostController.java`
- `backend/src/main/java/com/lukou/decision/service/PostService.java`（`create`）
- `backend/src/main/java/com/lukou/decision/dto/CreatePostReq.java`
- `backend/src/main/java/com/lukou/decision/entity/Post.java` / `Option.java` / `FollowUp.java`
- `miniprogram/pages/create/create.js` / `.wxml` / `.wxss` / `.json`（新增）
- `miniprogram/app.json`（注册页面）

**验证方式**
- 冒烟脚本创建决策成功返回 `id`，随后 `GET /api/posts/{id}` 可读到 3 个选项且顺序正确
- 数据库核对：`dv_post` 1 条、`dv_option` 3 条、`dv_follow_up` 1 条且 `due_at ≈ now + 3 月`
- 前端静态校验通过
