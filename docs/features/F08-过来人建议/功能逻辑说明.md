# F08 过来人建议（评论）

> **代码位置**：后端 `service/CommentService`、`service/PostService.buildComments`、`controller/CommentController`；前端 `pages/detail/detail.js` 建议区
> **状态**：✅ 已实现（核心差异化能力"我经历过/我只是路过"未落地，见第 9 节）
> **最后更新**：2026-11-26

## 1. 功能定位

决策下方的经验交流区。与普通评论的区别在于**每条建议可以带一个"结果标签"**——说这话的人自己选了、并且已经知道结果：值得 / 后悔 / 还在观察。

这一条把"意见"升级成"带后果的经验"。看建议的人一眼能分辨：说"值得"的人是已经熬过来了，还是刚上车还没挨打。

## 2. 用户视角流程

1. 详情页建议区，输入框 + 三个可选标签（值得 / 后悔 / 还在观察）
2. 标签是**可选**的，不选也能发；再点一次取消选择
3. 发布后立刻出现在列表顶部（按时间倒序）
4. 每条建议展示：昵称、头像、结果标签、内容、时间（截到分钟）

## 3. 业务规则

| 规则 | 说明 |
|---|---|
| 内容长度 | 必填，≤1000 字，过内容安全 |
| 结果标签 | 可选，值必须是 `worth` / `regret` / `watching`，其他值直接拒绝 |
| 关联选项 | `optionId` 可选，表示"我支持哪个选项"；当前前端未传 |
| 可见性 | 只返回 `status = 1` 的评论，逻辑删除用户不展示 |
| 排序与上限 | 时间倒序，单帖**最多返回 100 条**，无分页 |
| 权限 | 任意登录用户可发，不校验是否投过票、是否有相关经历 |
| 返回 | 创建接口返回单条 `CommentVO`；列表随详情接口一起返回 |

## 4. 数据结构

**表 `dv_comment`**

| 字段 | 说明 |
|---|---|
| post_id / user_id | 归属 |
| option_id | 支持哪个选项，可空 |
| content | 建议内容 ≤1000 |
| outcome_tag | worth / regret / watching，可空 |
| status | 1 正常 / 0 隐藏（人工处置用） |
| created_at | 时间 |

索引：`idx_post_created (post_id, created_at)` 支撑详情页倒序取 100 条。

## 5. 接口

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| POST | `/api/posts/{id}/comments` | 必须 | 发布建议 |

**请求**
```json
{
  "content": "我当年也纠结过，最后选了不接，代价是空了 5 个月，但换到了更匹配的方向",
  "outcomeTag": "worth"
}
```

**响应（`CommentVO`）**
```json
{
  "code": 0,
  "data": {
    "id": 33,
    "userName": "晚睡的512",
    "avatar": null,
    "content": "我当年也纠结过…",
    "outcomeTag": "worth",
    "optionLabel": null,
    "createdAt": "2026-11-26 19:20:03"
  }
}
```

列表不单独提供接口，`GET /api/posts/{id}` 的 `comments` 字段一并返回。

## 6. 后端实现

| 方法 | 关键逻辑 |
|---|---|
| `CommentService.create` | 查帖 → 校验标签枚举 → 过审 → 落库（`status = 1`）→ 组装 `CommentVO` 返回 |
| `PostService.buildComments` | 批量查作者（一次 `selectBatchIds`）、批量查选项 label（一次），避免逐条查询；标签原样透出，中文映射交给前端 |

## 7. 前端实现

| 方法 | 职责 |
|---|---|
| `onOutcomeTag` | 三选一，再点同一标签取消（`''`） |
| `addComment` | 校验非空 → 组装 `{content, outcomeTag?}` → 成功后清空输入与标签 → 重拉详情 |
| `decorate` | 把 `outcomeTag` 映射为中文 `outcomeLabel`，`createdAt` 截到分钟 |
| WXML | 标签用不同色块区分（值得/后悔/观察中），无标签则不渲染 |

## 8. 边界与异常

| 场景 | 表现 |
|---|---|
| 内容为空 | 前端 Toast「请写下你的建议」；后端 `@NotBlank` 400 |
| 标签非法（手工构造请求） | 400「结果标签不合法」 |
| 帖不存在 | 404 |
| 未登录 | 401 |
| 评论超过 100 条 | 只展示最近 100 条，更早的不可见（无分页，见第 9 节） |

## 9. 已知限制与待办

- [ ] **核心差异未落地**：产品设计里回答者要先声明"我经历过 / 我只是路过"，只有过来人的建议才该被重点展示。目前**任何人都能评论且权重相同**，`dv_experience` 也没参与判定。这是与竞品拉开差距最关键的一环，建议优先补：
  - 方案 A（轻）：发建议时强制选择身份，`dv_comment` 加 `author_type` 字段，前端分组展示
  - 方案 B（重）：按经历档案自动判定是否为"过来人"，无经历的用户只能投"路过"区
- [ ] **无分页**：单帖硬上限 100 条，热门帖会截断
- [ ] 无点赞、无回复、无 @，互动能力弱于竞品
- [ ] 无删除/编辑自己的建议
- [ ] **无举报入口**：UGC 产品过审通常要求可举报，`dv_report` 表已建但无接口（见 F11）
- [ ] 建议不展示作者星星与经历标签，无法判断"这人说的话有多少分量"
