# F08 过来人建议（评论）

> **代码位置**：后端 `service/CommentService`、`service/PostService.buildComments`、`controller/CommentController`；前端 `pages/detail/detail.js` 建议区
> **状态**：✅ 已实现（“我经历过 / 我只是路过”身份声明已落地，过来人建议优先展示）
> **最后更新**：2026-11-27

## 1. 功能定位

决策下方的经验交流区。与普通评论的区别在于**每条建议可以带一个"结果标签"**——说这话的人自己选了、并且已经知道结果：值得 / 后悔 / 还在观察。

这一条把"意见"升级成"带后果的经验"。看建议的人一眼能分辨：说"值得"的人是已经熬过来了，还是刚上车还没挨打。

## 2. 用户视角流程

1. 详情页建议区，先选身份：**我经历过 / 我只是路过**（必选）
2. 输入框 + 三个可选标签（值得 / 后悔 / 还在观察）
3. 标签是**可选**的，不选也能发；再点一次取消选择
4. 发布后，过来人建议排在路过建议之前；同身份内按时间倒序
5. 每条建议展示：昵称、身份徽标、结果标签、内容、时间（截到分钟）

## 3. 业务规则

| 规则 | 说明 |
|---|---|
| 内容长度 | 必填，≤1000 字，过内容安全 |
| 结果标签 | 可选，值必须是 `worth` / `regret` / `watching`，其他值直接拒绝 |
| 回答者身份 | `authorType`：`experienced` 我经历过 / `passerby` 我只是路过；不传按 `passerby` 兼容旧客户端 |
| 排序 | 详情接口组装时过来人优先，其次按 `created_at DESC` |
| 关联选项 | `optionId` 可选，表示"我支持哪个选项"；当前前端未传 |
| 可见性 | 只返回 `status = 1` 的评论，逻辑删除用户不展示 |
| 排序与上限 | 时间倒序，单帖**最多返回 100 条**，无分页 |
| 权限 | 任意登录用户可发，不校验是否投过票、是否有相关经历 |
| 返回 | 创建接口返回单条 `CommentVO`；列表随详情接口一起返回 |

## 4. 数据结构

**表 `dv_comment`**

| 字段 | 说明 |
|---|---|
| post_id / user_id | 归属 |
| option_id | 支持哪个选项，可空 |
| content | 建议内容 ≤1000 |
| outcome_tag | worth / regret / watching，可空 |
| author_type | experienced / passerby，默认 passerby |
| status | 1 正常 / 0 隐藏（人工处置用） |
| created_at | 时间 |

索引：`idx_post_created (post_id, created_at)` 支撑详情页倒序取 100 条。

## 5. 接口

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| POST | `/api/posts/{id}/comments` | 必须 | 发布建议 |

**请求**
```json
{
  "content": "我当年也纠结过，最后选了不接，代价是空了 5 个月，但换到了更匹配的方向",
  "outcomeTag": "worth",
  "authorType": "experienced"
}
```

**响应（`CommentVO`）**
```json
{
  "code": 0,
  "data": {
    "id": 33,
    "userName": "晚睡的512",
    "avatar": null,
    "content": "我当年也纠结过…",
    "outcomeTag": "worth",
    "optionLabel": null,
    "createdAt": "2026-11-26 19:20:03"
  }
}
```

列表不单独提供接口，`GET /api/posts/{id}` 的 `comments` 字段一并返回。

## 6. 后端实现

| 方法 | 关键逻辑 |
|---|---|
| `CommentService.create` | 查帖 → 校验标签/身份枚举 → 过审 → 落库（`status = 1`）→ 组装 `CommentVO` 返回 |
| `PostService.buildComments` | 批量查作者（一次 `selectBatchIds`）、批量查选项 label（一次）；按“过来人优先 + 时间倒序”排序后组装，标签原样透出 |

## 7. 前端实现

| 方法 | 职责 |
|---|---|
| `onCommentAuthorType` | 选择“我经历过 / 我只是路过”，再点一次取消 |
| `onOutcomeTag` | 三选一，再点同一标签取消（`''`） |
| `addComment` | 校验内容非空、身份已选 → 组装 `{content, outcomeTag?, authorType}` → 成功后清空输入/标签/身份 → 重拉详情 |
| `decorate` | 把 `outcomeTag` 映射为中文 `outcomeLabel`，`createdAt` 截到分钟 |
| WXML | 身份徽标 + 结果标签用不同色块区分；发布按钮在未选身份时禁用 |

## 8. 边界与异常

| 场景 | 表现 |
|---|---|
| 内容为空 | 前端 Toast「请写下你的建议」；后端 `@NotBlank` 400 |
| 标签非法（手工构造请求） | 400「结果标签不合法」 |
| 帖不存在 | 404 |
| 未登录 | 401 |
| 评论超过 100 条 | 只展示最近 100 条，更早的不可见（无分页，见第 9 节） |
