**涉及文件**

**验证方式**
- 手工接口验证：同一帖先发 `passerby` 再发 `experienced`，详情返回顺序为 experienced 在前，字段值正确
- `node --check detail.js` 通过；`smoke_test.py` 35 项断言全部通过

## 2026-11-26 · v0.1.0 · 新增

**摘要**：建议区支持"结果标签"，让意见带上后果；详情页一次性返回最近 100 条。

**实现内容**
- `POST /api/posts/{id}/comments`：内容 ≤1000 字、过审、标签枚举校验（worth/regret/watching）
- 详情接口 `comments` 字段批量组装：作者与选项 label 各一次批量查询，避免 N+1
- 前端建议区：输入 + 三标签可选（再点取消）+ 中文标签映射 + 时间截断
- 标签无值时整块不渲染，不占位

**新增/修改文件**
- `backend/src/main/java/com/lukou/decision/controller/CommentController.java`
- `backend/src/main/java/com/lukou/decision/service/CommentService.java`
- `backend/src/main/java/com/lukou/decision/service/PostService.java`（`buildComments`）
- `backend/src/main/java/com/lukou/decision/dto/CommentReq.java` / `CommentVO.java`
- `backend/src/main/resources/db/schema.sql`（`dv_comment`、`idx_post_created`）
- `miniprogram/pages/detail/detail.js`（`onOutcomeTag` / `addComment` / `decorate`）
- `miniprogram/pages/detail/detail.wxml` / `.wxss`

**验证方式**
- 冒烟脚本：发布带 `outcomeTag=worth` 的建议成功，详情返回的 `comments` 中携带该标签
- 后端编译通过，前端静态校验通过

**待补的关键能力（已记入功能说明第 9 节）**
- "我经历过 / 我只是路过"身份声明尚未实现，目前所有建议权重相同，这是与竞品的核心差异点
- 无分页（硬上限 100 条）、无举报入口
