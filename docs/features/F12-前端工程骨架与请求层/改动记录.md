## 2026-11-26 · v0.1.0 · 新增

**摘要**：小程序工程从官方模板起步，改造为业务骨架：5 页面四件套、单文件请求层、全局样式与通用页面模式。

**实现内容**
- 用官方 `native-basic` 模板初始化工程，改写 `project.config.json`（appid、项目名、`urlCheck: false`）
- `app.json`：注册 5 个页面、配置窗口与 3 项 tabBar（决策/案例库/我的）
- `utils/api.js`：`request` 统一封装（鉴权头、`code===0` 判定、401 清 token、15s 超时、统一错误结构）+ 21 个接口方法
- `app.js`：`onLaunch` 静默登录并缓存 profile；`refreshProfile()` 供页面主动刷新
- `app.wxss`：主色 `#185fa5` 的三级文字、卡片、按钮、chip、场景筛选条、结果标签三色、状态区、布局工具类
- 确立页面通用模式：`viewState` 四态、`decorate()` 数据加工、`loadXxx(reset)` 分页、`onShow` 刷新

**新增文件**
- `miniprogram/app.js` / `app.json` / `app.wxss` / `project.config.json` / `sitemap.json`
- `miniprogram/utils/api.js`
- `miniprogram/pages/index/*`、`pages/detail/*`、`pages/create/*`、`pages/cases/*`、`pages/profile/*`

**验证方式**
- 静态校验脚本（Node）：11 个 JSON 全部可解析、9 个 JS 通过 `node --check`、5 个 WXML 标签全部配对、事件绑定与 JS 方法一一对应、`app.json` 声明的页面文件齐全
- 后端启动后小程序可调通首页/详情/投票/方案全链路（冒烟脚本覆盖）

**踩坑记录**
- 官方模板在 Windows 安装包内被转成 CRLF，而 `manifest.json` 记录的是 LF 哈希，导致脚手架校验失败。把模板文件换行符规范化为 LF 后哈希全部匹配，成功展开。属工具链问题，与本工程代码无关
