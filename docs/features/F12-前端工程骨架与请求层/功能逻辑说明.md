# F12 前端工程骨架与请求层

> **代码位置**：`miniprogram/app.js`、`app.json`、`app.wxss`、`project.config.json`、`config.js`、`utils/api.js`
> **状态**：✅ 已实现
> **最后更新**：2026-11-27

## 1. 功能定位

不属于某个业务功能，但每个功能都依赖它：**页面注册、全局样式、登录态、请求封装、错误契约**。这层决定了新增一个页面要写多少样板代码。

## 2. 工程结构

```
miniprogram/
├── app.js                 全局逻辑：静默登录 + 资料缓存
├── app.json               路由、窗口、tabBar
├── app.wxss               全局通用样式（卡片/按钮/chip/状态区）
├── project.config.json    工程配置（AppID、编译选项）
├── config.js              环境配置：ENV（auto/dev/lan/tunnel/prod）、HOSTS、AUTO_ORDER、订阅模板 ID
├── sitemap.json
├── utils/
│   └── api.js             请求封装 + 选路逻辑 + 全部接口定义（单文件，无第三方依赖）
└── pages/
    ├── index/             首页信息流（tabBar）
    ├── detail/            决策详情（投票/方案/建议/回访）
    ├── create/            发起决策
    ├── cases/             案例库（tabBar）
    ├── login/             微信登录
    └── profile/           我的（tabBar）
```

每个页面固定四件套：`.js` / `.json` / `.wxml` / `.wxss`，共 6 个页面 24 个文件 + 7 个全局文件。

## 3. 配置要点

**`app.json`**
- `pages`：5 个页面，首页必须在第一位
- `window`：标题「路口 · 人生决策」、白底黑字、背景 `#f5f7fa`
- `tabBar`：3 项（决策 / 案例库 / 我的），**纯文字无图标**，选中色 `#185fa5`
- `lazyCodeLoading: "requiredComponents"`：按需注入

**`project.config.json`**
- `appid`：`wxd18a78dd1989306b`（**导入前确认与小程序后台一致**，不一致会提示无权限）
- `urlCheck: false`：本地联调免域名校验；线上以公众平台的合法域名配置为准
- `minified / minifyWXSS / minifyWXML`：上传压缩
- `miniprogramRoot: "./"`：工程根即小程序根

**`config.js`**
- `ENV`：`auto`（默认，自动选路）/ `dev`（模拟器）/ `lan`（强制局域网）/ `tunnel`（强制公网隧道）/ `prod`（线上 HTTPS）
- `HOSTS`：四档地址；`lan` 是电脑内网 IP，`tunnel` 是 `scripts/tunnel.sh` 打印的 `https://*.lhr.life`
- `AUTO_ORDER`：`auto` 模式的探测顺序，默认 `['lan','tunnel']`（先快后慢）
- `TMPL_FOLLOW_UP`：回访提醒模板 ID，留空则前端隐藏入口、后端跳过发送

**为什么需要 `auto`**：真机能否直连取决于网络环境，不由代码决定。公司/共享 WiFi 普遍开启客户端隔离（AP Isolation），同网段也互 ping 不通，表现为所有接口 `request:fail fail:time out`；此时无论怎么改内网 IP 都连不上，只能走公网隧道。把两条路都写进配置、让运行期自己选，比每次改代码可靠。

## 4. 请求层约定（`utils/api.js`）

| 约定 | 实现 |
|---|---|
| 基址 | `resolveBase()` 运行期决定，优先级：**手动地址**（storage `dv_api_manual`，小程序内可改）> `ENV!=='auto'` 时的 `HOSTS[ENV]` > `auto` 并发探测 `AUTO_ORDER`（`/api/health` 返回 `code===0` 者胜） |
| 手动地址 | 「我的」页顶部卡片可改，「手动 > 自动」；填了就不再探测，省掉首屏等待；清空即恢复自动选路 |
| 选路缓存 | 选中地址写 storage（`dv_api_host`）；请求失败调 `resetBase()` 清空，下次重新选路（换网 / IP 变化 / 隧道断线自愈） |
| 并发控制 | `resolveBase()` 是单例 Promise，首屏 11 个并发请求只触发一次探测 |
| Token | storage key `dv_token`，`getToken` / `setToken` / `removeToken` |
| 鉴权头 | 有 token 时自动加 `Authorization: Bearer {token}` |
| 成功判定 | HTTP 2xx **且** `body.code === 0` → `resolve(body.data)` |
| 401 | 清 token 并 `reject({code:401})`，提示"请先登录" |
| 其他失败 | `reject({ code, msg })`，`msg` 直接取后端文案 |
| 网络异常 | `reject({ code:-1, msg:'网络异常（连不上 host）' })`；全部候选都不通时列出试过的地址 |
| 超时 | 业务请求 15 秒；探测请求 3 秒 |

**接口方法清单（25 个）**：
- 基础：`health`、`login` / `ensureLogin`、`uploadAvatar`、`fileUrl`
- 决策帖：`feed` / `detail` / `createPost` / `myPosts` / `myVoted`、`vote`、`comments`、`report`
- 场景：`scenes`
- 方案：`solutions` / `addSolution` / `likeSolution` / `adoptSolution`
- 回访：`submitFollowUp` / `pendingFollowUps`、`subscribeStatus` / `grantSubscribe`
- 案例库：`cases` / `similarCases` / `caseStats`
- 我的：`profile` / `updateProfile` / `addExperience` / `deleteExperience`

新增接口只需在这里加一行，页面不直接写 `wx.request`。

## 6. 页面通用模式

| 模式 | 说明 |
|---|---|
| `viewState` 四态 | `loading` / `ready` / `empty` / `error`，用 `wx:if` 分支渲染，不用 `hidden` |
| `decorate()` | 后端原始数据 → 视图数据（时间截断、标签中文、`chosen` 标记），在 `setData` 前统一加工 |
| 分页 | `loadXxx(reset)`：`reset` 决定覆盖还是 `concat`；`hasMore` + `loading` 双重防抖 |
| 刷新时机 | `onShow` 从子页返回时重拉；`onPullDownRefresh` 下拉；`onReachBottom` 上拉 |
| 错误提示 | 统一 `wx.showToast({ title: err.msg, icon: 'none' })`，不弹 modal（除破坏性操作） |
| 时间格式 | 后端 `yyyy-MM-dd HH:mm:ss`，列表截到日、详情截到分钟 |

## 7. 边界与异常

| 场景 | 表现 |
|---|---|
| 后端未启动 | 所有候选地址探测失败 → `code:-1`，提示「网络异常（都连不上：地址 A / 地址 B）」，页面进 `error` 态 |
| 手机不在电脑局域网 | 局域网探测 3s 超时后自动降级到隧道，首屏慢 1–5s 但能加载；若隧道也没开则同上一行 |
| 隧道中途断开 | 当前请求失败 → `resetBase()` 清缓存 → 下次请求重新探测，恢复后自动可用 |
| 隧道域名轮换 | 旧域名失效 → 页面报「都连不上」→ 在「我的」页改一次服务器地址即可；卡片在所有状态之外，`error`/`guest` 态也能进 |
| 手动地址填错 | 不会自动清除（避免"改了又变回去"的困惑），页面持续报错并显示该地址，用户可自行改回 |
| Token 过期 | 401 自动清 token，下次请求触发重新登录 |
| JSON 解析失败 | 不会发生——`wx.request` 已按 `Content-Type` 自动解析 |
| 页面参数缺失 | 详情页无 `id` 时直接进 `error` 态「缺少话题编号」 |
