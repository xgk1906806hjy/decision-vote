## 2. 后端分层约定

```
Controller  → 只做参数接收、调用 Service、包装 R 返回
Service     → 业务规则、事务、审计、组装 VO
Mapper      → 数据访问（MyBatis-Plus，复杂统计用 @Select 手写 SQL）
Entity      → 与表一一对应，逻辑删除字段 deleted
DTO         → 入参 *Req / 出参 *VO，不直接暴露 Entity
```

- 所有接口统一返回 `R<T>`：`{"code":0,"msg":"ok","data":...}`。
- 业务错误抛 `BusinessException(code, msg)`，由 `GlobalExceptionHandler` 兜底。
- 需要登录的接口通过 `UserContext.require()` 取当前用户；返回 401 由拦截器处理。
- 逻辑删除：`dv_user` / `dv_post` / `dv_comment` / `dv_experience` 带 `deleted` 字段，MyBatis-Plus 自动过滤。

### 3.5 启动小程序

1. 微信开发者工具 → 导入项目 → 目录选 `E:\workspace\decision-vote\miniprogram`；
2. AppID 已写入 `project.config.json`（`wx5303985d08233359`），无需再填；
3. 详情 → 本地设置 → 勾选 **不校验合法域名**；
4. 确认 `miniprogram/config.js` 的 `ENV`，默认 `auto` 即可：
   - `auto`：启动时并发探测 `AUTO_ORDER`（`lan` → `server` → `tunnel`），谁先通用谁，选中地址缓存，请求失败自动清空重选；
   - `dev`：只给模拟器用（`localhost` 在手机上指手机自己）；
   - `lan`：强制局域网，需把 `HOSTS.lan` 改成电脑当前内网 IP；
   - `server`：强制走公网服务器（`HOSTS.server`，Nginx 反代），换任何网络都能连；
   - `tunnel`：强制公网隧道，地址由 `scripts/tunnel.sh` 打印；
   - `prod`：上线，必须是已备案 HTTPS 域名；
5. 编译预览。首次进入会自动 `wx.login` 换 token。

> **公网服务器是当前真机联调的首选**：`HOSTS.server` 指向已部署的服务器（Nginx 80 反代应用端口），手机用移动流量也能直连，不需要与电脑同网络、也不需要开隧道。`lan` 放在 `AUTO_ORDER` 首位只是因为它更快（同网段几毫秒），不通时 1.2 秒就自动跳过了。

> **改地址不用重新编译**：进入小程序「我的」页，顶部有「服务器地址」卡片（`prod` 环境自动隐藏），点「修改地址」粘贴新地址即可立即生效。存储 key 为 `dv_api_manual`，优先级高于 `config.js`；点「恢复自动」清除。这是应对免费隧道域名轮换的主要手段——`localhost.run` 实测 12–18 分钟换一次、`cpolar` 免费版 24 小时换一次，固定二级子域名需付费，所以不追求固定域名，而是把「换域名」的成本降到一次粘贴。
>
> **手机走流量时优先用 USB 直连**：手机与电脑无网络交集，内网 IP 不可达、隧道域名又老变。用数据线连上手机并打开「开发者选项 → USB 调试」，执行 `bash scripts/usb.sh`（内部 `adb reverse tcp:8080 tcp:8080`），再在「服务器地址」填 `http://localhost:8080`。走 USB 不过网络，零延迟、不轮换、无需注册；拔线重插后重跑脚本。

> 真机直连三要素：同一 WiFi、`HOSTS.lan` 是电脑当前内网 IP、Windows 防火墙放行 8080 入站（Private 配置档）。
> 电脑上先自测：`curl http://<内网IP>:8080/api/health` 返回 `{"code":0,...}` 才说明后端对外可达。
>
> **连不上时不要死磕内网 IP**：公司/共享 WiFi 普遍开启客户端隔离（AP Isolation），同网段也互 ping 不通，表现为所有接口 `request:fail fail:time out`（包被丢弃，不是被拒绝）。真机调试面板右侧「连接方式」若显示「其他」而非「局域网」，基本可确认手机不在电脑局域网内。此时执行 `bash scripts/tunnel.sh` 开公网隧道，把打印出的 `https://xxx.lhr.life` 填进 `HOSTS.tunnel` 即可；隧道仅适合联调，域名会轮换、带宽有限。
>
> `auto` 模式全部候选失败时，前端提示会列出试过的地址（「网络异常（都连不上：a / b）」），照着一个个 `curl` 就能定位是哪一层断了。

### 5.2 核心关系

```
dv_user 1 ── n dv_post 1 ── n dv_option
                 │              │
                 │              └── n dv_vote（user × option，唯一约束）
                 ├── n dv_solution ── n dv_solution_like
                 ├── n dv_comment
                 └── 1  dv_follow_up（有记录 = 已成案例）

dv_user 1 ── n dv_experience
dv_user 1 ── n dv_user_credit（按场景累计星星，总数 = SUM(stars)）
```

## 6. 接口清单

统一前缀 `/api`，统一返回 `R<T>`。鉴权列：`—` 表示可匿名访问，`✔` 表示必须带 `Authorization: Bearer <token>`。

| POST | `/auth/login` | — | `{code, nickname?, avatar?}` | `{token, userId, nickname, avatar, newUser}` |

`CaseVO` 字段：`postId, title, content, scene, chosenLabel, outcome, outcomeLabel, outcomeNote, voteCount, commentCount, answeredAt, similarity`。

`CaseStatsVO` 字段：`total, worth, regret, watching, unknown, worthRate, regretRate, watchingRate, scenes[{scene, total, worth, regret, watching, worthRate, regretRate}]`。比例分母为已表态数（不含 `unknown`），`scenes` 最多 6 项、按案例数倒序；传 `scene` 时顶层数字只看该场景，`scenes` 始终为全景。

### 6.11 微信消息推送回调

由微信服务器调用，**不带 JWT**，靠签名鉴权（`WebConfig` 已放行 `/api/wx/callback`）。

| 方法 | 路径 | 鉴权 | 入参 | 出参 |
|---|---|---|---|---|
| GET | `/wx/callback` | 签名 | `signature`、`timestamp`、`nonce`、`echostr` | `echostr` 原文 |
| POST | `/wx/callback` | 签名 | `signature`、`timestamp`、`nonce` + 事件体（JSON 或 XML） | `success` |

- 签名：`sha1(sort(WX_MEDIA_TOKEN, timestamp, nonce))`，比对用 `MessageDigest.isEqual`
- `WX_MEDIA_TOKEN` 未配置时直接拒绝，不提供空 token 放行
- 只处理 `Event=wxa_media_check`；XML 解析关闭 DTD / 外部实体（防 XXE）
- 无论处理成败都返回 `success`，避免微信重试；重复推送按 `trace_id` 覆盖写，幂等

## 7. 登录流程

```
小程序                    后端                        微信
  │  wx.login()             │                          │
  │──── code ───────────────▶                          │
  │                         │  code2Session ───────────▶│
  │                         │◀── openid ────────────────│
  │                         │  查/建 dv_user            │
  │◀── {token,userId,...} ──│  签发 JWT（720h）         │
  │  存 storage dv_token    │                          │
```

- `WX_MOCK=true` 时不调微信接口，直接用 code 派生 openid，方便本地调试。
- 后续所有请求由 `utils/api.js` 自动附加 `Authorization: Bearer <token>`。
- 401 时自动清 token，前端提示重新进入。

## 8. 前端约定

- **请求层**：只通过 `utils/api.js` 访问后端，页面里不直接写 `wx.request`。
- 返回处理：`code===0` 视为成功并直接返回 `data`；否则 reject `{code, msg}`，页面用 `wx.showToast` 提示 `err.msg`。
- **页面状态**：统一三态 `viewState = loading | ready | error`，错误态提供"点击重试"。
- **样式**：全局样式在 `app.wxss`，定义 `.page`、`.card`、`.primary-btn`、`.scene-tag`、`.muted`、`.flex-row`、`.spacer` 等基础类；页面样式只写差异部分。
- **单位**：`rpx`；主色沿用全局定义（避免页面里写死颜色）。
- **WXML 规范**：列表必须带 `wx:key`；条件渲染用 `wx:if / wx:elif / wx:else`。

## 9. 关键业务实现说明

### 9.1 盲投
`PostService.buildCards` 中：
```java
boolean revealed = Objects.equals(post.getUserId(), userId)   // 发起者
        || (userId != null && myVoteMap.containsKey(post.getId()))  // 已投票
        || "closed".equals(status);                            // 已截止
```
未揭晓时把每个选项的 `count/percent` 置 0，并置 `blind=true`，前端据此显示"已有 N 人参与"而非进度条。

### 9.2 采纳与星星
`SolutionService.adopt`：校验发起者身份 → 校验方案属于该帖 → 校验未重复采纳 → `adopted=1` → `dv_user_credit(user_id, scene)` 上 `stars+1`（不存在则插入）→ 重新查询时 `authorStars` 为该用户所有场景星星之和。

### 9.3 案例库
`CaseService` 以 `dv_follow_up.answered_at IS NOT NULL` 为条件关联 `dv_post`，拼接最终选项 label 与结局文案，输出 `CaseVO`；`similar` 按 `scene` 精确 + `keyword` 模糊打分排序。

`CaseService.stats` 复用同一入池条件，在内存里按 `outcome` 与 `post.scene` 双维度累加，比例 = `Math.round(count * 100.0 / 已表态数)`，场景按案例数倒序取前 6。目前是全量遍历聚合，案例量级上升后应改为 SQL `GROUP BY`。

### 9.4 过期状态落库
`PostStatusJob` 由 `@EnableScheduling` 驱动，默认每 60 秒执行一次：
```sql
UPDATE dv_post
SET status = 'closed'
WHERE deleted = 0 AND status = 'open'
  AND deadline IS NOT NULL AND deadline <= NOW();
```
读取侧 `PostService.effectiveStatus` 仍按 `deadline` 兜底，投票侧 `VoteService` 也直接校验 `deadline`，因此任务延迟不会放开投票；落库的目的是让后台统计、筛选和 `idx_status_created` 索引看到真实状态。间隔可用 `POST_CLOSE_INTERVAL_MS` 覆盖。

### 9.5 回访订阅提醒
`FollowUpReminderJob` 每天 10:00 触发 `FollowUpReminderService.runOnce()`：

1. 前置判断：模板未配置 → `template-not-configured`；`WX_MOCK=true` 且非 dry-run → `wx-mock`
2. 候选：`answered_at IS NULL` + `due_at <= now` + `reminded_at IS NULL` + `due_at >= now - max-age-days`，按 `due_at` 升序取 `batch-size`
3. 逐条：查帖（已删则标记跳过）→ 查 openid → 查额度（0 则跳过且**不标记**，等用户授权后再推）
4. 发送成功：`remain - 1` + 写 `reminded_at`；43101/47003：额度清零 + 写 `reminded_at`；其他错误：不标记，下轮重试

额度存 `dv_subscribe.remain`（授权 +1、发送 -1、上限 10），与 `reminded_at` 分离存储——额度管"能不能发"，`reminded_at` 管"这一条发过没有"，用户重新授权后旧记录不会被误判为已推。

微信模板字段约定：`thing1` = 决策标题（截断 20 字）、`time2` = 计划回访时间、`thing3` = 引导语。换模板需同步改 `FollowUpReminderService.buildData`。

### 9.6 场景标签（预设 + 自定义）

`SceneService.PRESET` 存 8 个预设；`list()` 用一条 `SELECT scene, COUNT(*) ... GROUP BY scene ORDER BY COUNT(*) DESC LIMIT 40` 取真实使用情况，再在内存里跳过预设项、追加最多 6 个自定义场景。

发布时 `PostService.create` 调 `SceneService.normalize()`：trim → 空拒绝 → 超 10 字拒绝，随后 `audit.check(scene)` 走内容安全。**场景不建独立表**，它就是 `dv_post.scene` 上的一个标签；建表会带来"删除场景时历史帖子怎么办"的歧义。

不做同义合并（"考公"与"公务员"各自成池），宁可分裂也不擅自替用户归一；后续要归一应加 `scene_alias` 映射表在展示层处理。

### 9.7 头像上传

`FileController.avatar` 只做四件事：校验登录 → 校验大小（≤2MB）→ 按**文件头**判图片类型（`FFD8FF`/`PNG`/`RIFF..WEBP`）→ 落盘 `uploads/avatar/yyyyMM/{uuid}.{ext}`。

- 不信任 `Content-Type` 与扩展名，防止改后缀上传可执行内容
- 文件名完全服务端生成，杜绝路径穿越与覆盖
- 库里存相对路径 `/uploads/...`，`WebConfig` 把上传目录映射到 `/uploads/**`；换了域名只改 `UPLOAD_PUBLIC_BASE`，不用刷库
- 前端 `api.fileUrl()` 负责把相对路径拼成完整地址，渲染处不关心环境

已知取舍：文件只增不删（换头像留孤儿），且依赖本机磁盘，多实例部署需换对象存储。

### 9.8 头像异步送审

微信的图片审核是异步的：提交只返回 `trace_id`，结果推送到「消息推送」配置的回调地址。所以头像走「先展示、事后回收」。

- **提交**：`FileController` 落盘后调 `submitMediaCheck`，`AUDIT_MOCK=true`、URL 非 `http`（未配 `UPLOAD_PUBLIC_BASE`）、openid 为 `mock_*` 三种情况跳过；失败只打 warn，不阻塞上传
- **回调**：`/api/wx/callback` 按 `trace_id` 找回 `dv_media_check`，`errcode!=0 → status=3`；`pass/review → 1`；`risky → 2` 并清空头像
- **防误伤**：清空前比对 `dv_user.avatar` 是否仍包含该 `media_path`，用户已换新头像则不动
- **配置前提**：`AUDIT_MOCK=false`、`UPLOAD_PUBLIC_BASE` 指向公网可访问地址（微信要能拉到图）、`WX_MEDIA_TOKEN` 与公众平台一致

## 12. 生产部署流程

本章假设部署形态为**自建 Linux 服务器 + 已备案域名 + 微信小程序**，与云开发无关。本地开发请回到第 3 节。

### 12.1 关键路径

ICP 备案是唯一无法靠技术压缩的步骤（个人主体 7–20 个工作日），**第一天就要启动**。其余步骤与备案并行准备。

| 顺序 | 动作 | 前置 | 备注 |
|---|---|---|---|
| 1 | 买域名、买服务器、提交 ICP 备案 | — | 备案耗时最长 |
| 2 | 服务器装环境、本地构建 jar | 与 1 并行 | 不依赖备案 |
| 3 | DNS A 记录指向服务器、签 HTTPS 证书 | 备案通过 | 未备案无法配小程序合法域名 |
| 4 | 建库建账号、上传 jar、写环境变量、systemd 启动 | 2 | 先用 IP + 自签证书自测 |
| 5 | Nginx 反代 443 → 8080 | 3、4 | 证书就位后切 HTTPS |
| 6 | 小程序 `config.js` 切 `prod`、配合法域名、上传提审 | 5 | 审核 1–7 天 |
| 7 | 发布、验收、监控 | 6 | — |

> - **8080 被 Jenkins 占用** → 应用监听 `127.0.0.1:8081`，Nginx 80 反代到 8081；安全组只需放行 22 / 80 / 443
> - **MySQL 跑在 docker 容器 `mysql` 里** → 建库走 `docker exec` 而不是本机 `mysql` 客户端，密码由 `MYSQL_ROOT_PASSWORD` 环境变量提供

### 12.5 生产环境变量

创建 `/opt/decision-vote/decision-vote.env`（**权限设为 600**）：

```bash
cat > /opt/decision-vote/decision-vote.env <<'EOF'
DB_USERNAME=dvapp
DB_PASSWORD=换成强密码
SPRING_DATASOURCE_URL=jdbc:mysql://localhost:3306/decision_vote?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
JWT_SECRET=用 openssl rand -hex 32 生成
WX_APPID=wx你的真实AppID
WX_SECRET=你的真实AppSecret
WX_MOCK=false
AUDIT_MOCK=false
ADMIN_TOKEN=换成随机长串
FOLLOW_UP_TMPL_ID=你的订阅消息模板ID
EOF
chmod 600 /opt/decision-vote/decision-vote.env
```

几个关键点：

- **`SPRING_DATASOURCE_URL` 必须显式设置**。`application.yml` 里数据源 URL 是写死的 `localhost:3306`，Spring Boot 的环境变量优先级高于配置文件，设置它可以覆盖；如果 MySQL 不在本机，改这里的 host 即可。
- `JWT_SECRET` 用 `openssl rand -hex 32` 生成，不要复用默认值。
- `WX_MOCK=false` 后登录会真实调微信 `code2Session`，`WX_APPID` / `WX_SECRET` 必须与小程序后台一致。
- `AUDIT_MOCK=false` 后会调微信内容安全 `msgSecCheck`，需把**服务器公网出口 IP** 加入公众平台「开发 → 开发管理 → 开发设置 → IP 白名单」。
- `FOLLOW_UP_TMPL_ID` 与小程序 `utils/api.js` 里的 `TMPL_FOLLOW_UP` 必须填同一个模板 ID；两边任一为空，提醒功能自动降级为"只显示待回访、不推送"。上线前记得在公众平台「订阅消息」里选好模板，并核对模板字段名是否为 `thing1 / time2 / thing3`。
- 生产建议关掉 SQL 打印：在 env 文件追加 `MYBATIS_PLUS_CONFIGURATION_LOG_IMPL=org.apache.ibatis.logging.nologging.NoLoggingImpl`。默认配置是 `StdOutImpl`，会把每条 SQL 打到日志里。

### 12.6 systemd 托管

创建 `/etc/systemd/system/decision-vote.service`：

```ini
[Unit]
Description=Decision Vote API
After=network-online.target mysql.service
Wants=network-online.target mysql.service

[Service]
Type=simple
User=root
WorkingDirectory=/opt/decision-vote
EnvironmentFile=/opt/decision-vote/decision-vote.env

```

> `User=root` 是为了减少首次部署的权限问题；生产更稳妥的做法是建 `deploy` 用户并给它 `/opt/decision-vote` 和日志目录的写权限。

启动并验证：


### 12.7 Nginx 反代与 HTTPS

先写仅 80 端口的配置让证书签发能通：

```nginx
# /etc/nginx/conf.d/decision-vote.conf
server {
    listen 80;
    server_name api.example.com;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
        client_max_body_size 2m;
    }
}
```

```bash
nginx -t && systemctl reload nginx
certbot --nginx -d api.example.com --agree-tos -m 你的邮箱 --non-interactive
```

certbot 会自动签发证书并把 80 改成 443 + HTTP 跳转。它同时会注册 systemd timer 自动续期，验证续期：

```bash
certbot renew --dry-run
```

如果你想手写完整 HTTPS 配置，替换成下面这段：

```nginx
server {
    listen 80;
    server_name api.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name api.example.com;

    ssl_certificate     /etc/letsencrypt/live/api.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/api.example.com/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
        client_max_body_size 2m;
    }
}
```

> 微信小程序要求 HTTPS 且 TLS ≥ 1.2、证书链完整、域名与合法域名完全一致（含大小写和端口）。`api.example.com` 只是一个域名示例，可复用主域名的子域名。

### 12.8 小程序端发布

1. 把 `miniprogram/config.js` 切到生产环境：
   ```js
   const ENV = 'prod';
   const HOSTS = { /* ... */ prod: 'https://api.example.com' };
   ```
   地址只在这一处维护，`api.js` 从中读取 `config.BASE_URL`。
2. 公众平台 → 开发管理 → 开发设置 → **服务器域名** → `request 合法域名` 加入 `https://api.example.com`。改完后重新打开开发者工具才会生效；`project.config.json` 里的 `urlCheck` 只影响本地开发者工具，线上以公众平台配置为准。
3. 确认 `project.config.json` 的 `appid` 与公众平台一致。注意历史上有过两个 AppID（`wx5303985d08233359` 与 `wxd18a78dd1989306b`），**以你在公众平台实际看到的为准**，不一致会提示无权限。
4. 开发者工具 → 上传 → 填版本号（如 `1.0.0`）与备注。
5. 公众平台 → 版本管理 → 提交审核。服务类目按「工具」申报，页面文案避免出现社交/社区/论坛表述。
6. 审核通过后发布，并在真机上走一遍：进入首页 → 投票 → 提交方案 → 发起决策。
