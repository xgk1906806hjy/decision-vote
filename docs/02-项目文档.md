## 2. 后端分层约定

```
Controller  → 只做参数接收、调用 Service、包装 R 返回
Service     → 业务规则、事务、审计、组装 VO
Mapper      → 数据访问（MyBatis-Plus，复杂统计用 @Select 手写 SQL）
Entity      → 与表一一对应，逻辑删除字段 deleted
DTO         → 入参 *Req / 出参 *VO，不直接暴露 Entity
```

- 所有接口统一返回 `R<T>`：`{"code":0,"msg":"ok","data":...}`。
- 业务错误抛 `BusinessException(code, msg)`，由 `GlobalExceptionHandler` 兜底。
- 需要登录的接口通过 `UserContext.require()` 取当前用户；返回 401 由拦截器处理。
- 逻辑删除：`dv_user` / `dv_post` / `dv_comment` / `dv_experience` 带 `deleted` 字段，MyBatis-Plus 自动过滤。

## 5. 数据库设计

### 5.1 表清单

| 表名 | 说明 | 关键约束 |
|---|---|---|
| `dv_user` | 用户 | `uk_openid(openid)` |
| `dv_experience` | 经历档案（场景/选择/距今几年/结果） | `idx_user`、`idx_scene` |
| `dv_post` | 决策帖 | `idx_status_created`、`idx_scene` |
| `dv_option` | 选项（2–6 个） | `idx_post` |
| `dv_vote` | 投票记录 | **`uk_post_user(post_id,user_id)` 防重复投** |
| `dv_comment` | 建议/评论（带 outcome_tag） | `idx_post_created` |
| `dv_follow_up` | 回访结果（决策→结局） | **`uk_post(post_id)` 一帖一条** |
| `dv_report` | 举报 | `idx_target` |
| `dv_solution` | 用户补充的方案 | `idx_post(post_id,adopted)` |
| `dv_solution_like` | 方案点赞 | **`uk_solution_user` 防重复赞** |
| `dv_user_credit` | 场景星星（`uk_user_scene`） | **`uk_user_scene(user_id,scene)`** |

### 5.2 核心关系

```
dv_user 1 ── n dv_post 1 ── n dv_option
                 │              │
                 │              └── n dv_vote（user × option，唯一约束）
                 ├── n dv_solution ── n dv_solution_like
                 ├── n dv_comment
                 └── 1  dv_follow_up（有记录 = 已成案例）

dv_user 1 ── n dv_experience
dv_user 1 ── n dv_user_credit（按场景累计星星，总数 = SUM(stars)）
```

### 5.3 结局枚举

`outcome` 统一取值：`worth`（值得）/ `regret`（后悔）/ `watching`（观察中）。
前端展示映射：值得 / 后悔 / 还在观察。

## 7. 登录流程

```
小程序                    后端                        微信
  │  wx.login()             │                          │
  │──── code ───────────────▶                          │
  │                         │  code2Session ───────────▶│
  │                         │◀── openid ────────────────│
  │                         │  查/建 dv_user            │
  │◀── {token,userId,...} ──│  签发 JWT（720h）         │
  │  存 storage dv_token    │                          │
```

- `WX_MOCK=true` 时不调微信接口，直接用 code 派生 openid，方便本地调试。
- 后续所有请求由 `utils/api.js` 自动附加 `Authorization: Bearer <token>`。
- 401 时自动清 token，前端提示重新进入。

## 8. 前端约定

- **请求层**：只通过 `utils/api.js` 访问后端，页面里不直接写 `wx.request`。
- 返回处理：`code===0` 视为成功并直接返回 `data`；否则 reject `{code, msg}`，页面用 `wx.showToast` 提示 `err.msg`。
- **页面状态**：统一三态 `viewState = loading | ready | error`，错误态提供"点击重试"。
- **样式**：全局样式在 `app.wxss`，定义 `.page`、`.card`、`.primary-btn`、`.scene-tag`、`.muted`、`.flex-row`、`.spacer` 等基础类；页面样式只写差异部分。
- **单位**：`rpx`；主色沿用全局定义（避免页面里写死颜色）。
- **WXML 规范**：列表必须带 `wx:key`；条件渲染用 `wx:if / wx:elif / wx:else`。

## 9. 关键业务实现说明

### 9.1 盲投
`PostService.buildCards` 中：
```java
boolean revealed = Objects.equals(post.getUserId(), userId)   // 发起者
        || (userId != null && myVoteMap.containsKey(post.getId()))  // 已投票
        || "closed".equals(status);                            // 已截止
```
未揭晓时把每个选项的 `count/percent` 置 0，并置 `blind=true`，前端据此显示"已有 N 人参与"而非进度条。

### 9.2 采纳与星星
`SolutionService.adopt`：校验发起者身份 → 校验方案属于该帖 → 校验未重复采纳 → `adopted=1` → `dv_user_credit(user_id, scene)` 上 `stars+1`（不存在则插入）→ 重新查询时 `authorStars` 为该用户所有场景星星之和。

### 9.3 案例库
`CaseService` 以 `dv_follow_up.answered_at IS NOT NULL` 为条件关联 `dv_post`，拼接最终选项 label 与结局文案，输出 `CaseVO`；`similar` 按 `scene` 精确 + `keyword` 模糊打分排序。

## 12. 生产部署流程

本章假设部署形态为**自建 Linux 服务器 + 已备案域名 + 微信小程序**，与云开发无关。本地开发请回到第 3 节。

### 12.1 关键路径

ICP 备案是唯一无法靠技术压缩的步骤（个人主体 7–20 个工作日），**第一天就要启动**。其余步骤与备案并行准备。

| 顺序 | 动作 | 前置 | 备注 |
|---|---|---|---|
| 1 | 买域名、买服务器、提交 ICP 备案 | — | 备案耗时最长 |
| 2 | 服务器装环境、本地构建 jar | 与 1 并行 | 不依赖备案 |
| 3 | DNS A 记录指向服务器、签 HTTPS 证书 | 备案通过 | 未备案无法配小程序合法域名 |
| 4 | 建库建账号、上传 jar、写环境变量、systemd 启动 | 2 | 先用 IP + 自签证书自测 |
| 5 | Nginx 反代 443 → 8080 | 3、4 | 证书就位后切 HTTPS |
| 6 | 小程序改 `BASE_URL`、配合法域名、上传提审 | 5 | 审核 1–7 天 |
| 7 | 发布、验收、监控 | 6 | — |

### 12.5 生产环境变量

创建 `/opt/decision-vote/decision-vote.env`（**权限设为 600**）：

```bash
cat > /opt/decision-vote/decision-vote.env <<'EOF'
DB_USERNAME=dvapp
DB_PASSWORD=换成强密码
SPRING_DATASOURCE_URL=jdbc:mysql://localhost:3306/decision_vote?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
JWT_SECRET=用 openssl rand -hex 32 生成
WX_APPID=wx你的真实AppID
WX_SECRET=你的真实AppSecret
WX_MOCK=false
AUDIT_MOCK=false
EOF
chmod 600 /opt/decision-vote/decision-vote.env
```

几个关键点：

- **`SPRING_DATASOURCE_URL` 必须显式设置**。`application.yml` 里数据源 URL 是写死的 `localhost:3306`，Spring Boot 的环境变量优先级高于配置文件，设置它可以覆盖；如果 MySQL 不在本机，改这里的 host 即可。
- `JWT_SECRET` 用 `openssl rand -hex 32` 生成，不要复用默认值。
- `WX_MOCK=false` 后登录会真实调微信 `code2Session`，`WX_APPID` / `WX_SECRET` 必须与小程序后台一致。
- `AUDIT_MOCK=false` 后会调微信内容安全 `msgSecCheck`，需把**服务器公网出口 IP** 加入公众平台「开发 → 开发管理 → 开发设置 → IP 白名单」。
- 生产建议关掉 SQL 打印：在 env 文件追加 `MYBATIS_PLUS_CONFIGURATION_LOG_IMPL=org.apache.ibatis.logging.nologging.NoLoggingImpl`。默认配置是 `StdOutImpl`，会把每条 SQL 打到日志里。

### 12.7 Nginx 反代与 HTTPS

先写仅 80 端口的配置让证书签发能通：

```nginx
# /etc/nginx/conf.d/decision-vote.conf
server {
    listen 80;
    server_name api.example.com;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
        client_max_body_size 2m;
    }
}
```

```bash
nginx -t && systemctl reload nginx
certbot --nginx -d api.example.com --agree-tos -m 你的邮箱 --non-interactive
```

certbot 会自动签发证书并把 80 改成 443 + HTTP 跳转。它同时会注册 systemd timer 自动续期，验证续期：

```bash
certbot renew --dry-run
```

如果你想手写完整 HTTPS 配置，替换成下面这段：

```nginx
server {
    listen 80;
    server_name api.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name api.example.com;

    ssl_certificate     /etc/letsencrypt/live/api.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/api.example.com/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
        client_max_body_size 2m;
    }
}
```

> 微信小程序要求 HTTPS 且 TLS ≥ 1.2、证书链完整、域名与合法域名完全一致（含大小写和端口）。`api.example.com` 只是一个域名示例，可复用主域名的子域名。
